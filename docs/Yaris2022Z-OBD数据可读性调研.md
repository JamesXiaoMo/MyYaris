# 日本 2022 款丰田 Yaris Z 混动 OBD-II 数据可读性与车机系统架构调研报告

> **调研对象**：日本本土版 2022 年款丰田 Yaris（ヤリス）Z 混动版（1.5L HYBRID）
> **硬件配件**：Veepeak OBDCheck BLE+ 蓝牙 4.0 双模 OBD2 扫描器（Amazon ASIN: `B07VP1NHHX`）
> **宿主系统**：Ottocast P3 Pro 车机盒子（Android 13 / arm64）+ Flutter `car_app`
> **报告性质**：**只读技术调研与架构可行性论证**（不连接实车、不写 ECU、不清除 DTC、不执行任何主动控制）

---

### 1. 硬件配件核实与官方规格核对

### 1.1 ASIN 对应产品精确核实与版本界定
经 Amazon 日本实际商品页面（ASIN: `B07VP1NHHX`）与 Veepeak 官方手册技术资料交叉核对：
- **Amazon 日本商品准确标题**：`【BimmerCode 公式】 OBDCheck BLE+ Bluetooth オフィシャルサポート BMW/MINIのコーディング`（商品标识 ASIN: `B07VP1NHHX`）
- **核实产品型号**：**Veepeak OBDCheck BLE+**（为带加号的「Plus」增强版本，非基础款 OBDCheck BLE）
- **固件指令集版本差异（官方技术文档记载）**：
  - **基础款 OBDCheck BLE**：采用 **ELM327 v1.4** 兼容指令集，缓冲区较小，不支持部分高级扩展指令。
  - **增强款 OBDCheck BLE+ (ASIN: B07VP1NHHX)**：支持扩展至 **ELM327 v2.2** AT 指令集，具备更大单帧/多帧数据接收缓冲区，支持 `AT SH`（设置 CAN 请求报头）、`AT CRA`（设置 CAN 接收过滤器）等进阶多帧分段重组指令。
- **官方指导通信模式与平台差异**：
  - **iOS 端**：基于 **Bluetooth Low Energy (BLE 4.0 / GATT)** 协议通信。官方手册强调**切勿在 iOS 系统蓝牙设置中配对**，必须在各诊断 App 内直接扫描 GATT 服务建立连接。
  - **Android 端**：官方用户手册的标准指引为**传统蓝牙 (Bluetooth Classic SPP)** 模式，需先在 Android 系统「蓝牙设置」中输入 PIN 码（`1234` 或 `0000`）完成系统配对，再在 App 中选择 Bluetooth 连接。虽然部分第三方 App（如 Car Scanner）支持直接通过 BLE GATT 发现该设备，但官方文档并未将 Android BLE 作为标准保证途径。
- **物理与车载协议规格**：
  - 物理接口：标准 SAE J1962 16 针 OBD-II 接口
  - 核心协议：**ISO 15765-4 CAN**（11-bit / 29-bit, 500 kbaud & 250 kbaud）、ISO 14230-4 KWP2000、ISO 9141-2、SAE J1850 VPW/PWM
  - 供电机制：车辆 OBD Pin 16 常电（Battery 12V）供电，工作电流约 35~45mA。

### 1.2 日本 J-OBD / J-OBD II 协议兼容边界
- **法规背景**：日本国土交通省自 2008 年 10 月起对本土新型乘用车强制执行 **J-OBD II** 诊断法规，接口规范统一采用 ISO 15765-4 CAN 协议。
- **兼容边界判定**：2022 款日本 Yaris（XP210 系）OBD 物理接口（DLC3，位于方向盘左下方护板内侧）的 CAN-H (Pin 6)、CAN-L (Pin 14) 物理引脚和波特率与 Veepeak 适配器支持的 ISO 15765-4 CAN 11-bit 500k 匹配。
- **撤回过度承诺**：**物理引脚与底层协议匹配并不等同于“100% 兼容”**。车辆各子 ECU 是否对 OBD 端口开放查询、开放哪些标准 PID、是否受中央网关策略拦截，完全取决于丰田实车软件固件设定，绝非通配保证。

### 1.3 Ottocast P3 Pro 车机盒子连接可行性客观评估
- **厂商官方预警**：Veepeak 官方手册明确提示 *“Android car stereos/head units are generally not recommended or compatible”*（后装安卓车机/大屏通常不推荐或可能存在兼容问题）。
- **实机只读检查现状**：
  - 在当前连接的 Ottocast P3 Pro 车机盒子（Android 13 / arm64，高通 6125 平台）执行只读服务核查，系统特性列表中确实注册了 `feature:android.hardware.bluetooth` 与 `feature:android.hardware.bluetooth_le`。
- **保留项与限制**：
  - **具备系统 BLE 特性 ≠ 证明实测可以成功连接并稳定透传**。
  - 车机安卓系统的蓝牙协议栈通常高度定制（用于 CarPlay/Android Auto 宿主互联或免提电话），可能存在后台蓝牙串口权限被杀、配对弹窗被拦截、或 GATT 连接断连问题，必须经过实车配对验证，不可预先定论。

## 3. 可读取信息分级能力矩阵（基于证据边界的客观评估）

在 OBD-II 诊断体系中，任何数据的实际可用性都**受制于具体实车的 ECU 固件开放策略**。标准通用 PID 必须在实车上通过支持位图（Supported Bitmap）逐项确认，不能仅凭理论假设。

根据目前掌握的官方证据与协议规范，将数据读取能力划分为 **三档**：

---

### 3.1 第一档：优先可读候选（标准 SAE J1979 OBD-II Mode 01，需实车位图验证）

通过标准 11 位 CAN 广播或发动机 ECM 查询。所有参数必须在实车上通过 `0100` / `0120` / `0140` 返回的支持位图判定是否真实开放；且在混动工况下（发动机点火 vs 纯电停机）读数表现具有动态差异。

| PID 编号 | 参数名称 | 数据含义与实车行为 | 混动工况特殊性与可用性判定 |
| :---: | :--- | :--- | :--- |
| `0x00` | Supported PIDs [01-20] | 支持位图 1~20 | **必须优先查询**。决定后续 01~20 PID 是否支持 |
| `0x05` | Engine Coolant Temp (ECT) | 发动机冷却液水温 (°C) | **优先候选**。冷车暖机与热机判定指标，水温传感器持续在线 |
| `0x0C` | Engine RPM | 发动机实际转速 (rpm) | **优先候选**。纯电 EV 滑行/停机时读数瞬时为 `0` |
| `0x0D` | Vehicle Speed | 车速 (km/h) | **优先候选**。全工况有效 |
| `0x0F` | Intake Air Temp (IAT) | 进气温度 (°C) | **优先候选**。进气传感器温度 |
| `0x11` | Throttle Position | 节气门开度 (%) | **优先候选**。电子节气门开度；纯电停机时维持怠速位或关断 |
| `0x04` | Calculated Engine Load | 计算发动机负荷 (%) | **优先候选**。纯电驱动停机时为 `0%` |
| `0x10` | Mass Air Flow (MAF) | 进气质量流量 (g/s) | **优先候选**。纯电停机时为 `0 g/s` |
| `0x42` | Control Module Voltage | 控制模块供电电压 (V) | **特别澄清**：此为 ECU 内部集成芯片的逻辑供电电压，**不等于 12V 辅助蓄电池两端的精确开路端电压** |
| `0x06`/`0x07` | STFT / LTFT | 短期/长期燃油修正 (%) | **条件候选**。仅在发动机点火且进入闭环（Closed Loop）时有有效数值 |
| `0x5E` | Engine Fuel Rate | 发动机燃油消耗率 (L/h) | **条件候选**。标准 SAE Mode 01 定义的燃油流速 PID，需实车位图支持；若不支持则由车机根据 MAF 流量估算 |
| `0x2F` | Fuel Tank Level Input | 油箱燃油剩余液位 (%) | **条件候选 / 大概率不支持**。丰田混动车型油箱浮子传感器通常连接至仪表总线，发动机 ECM 通用 `012F` 请求常返回 `NO DATA` |
| `Mode 03/07` | DTC 故障码读取 | 读取已存储/待决故障码 | **只读支持**。仅读取排放与动力系统标准故障码 |
| `Mode 02` | Freeze Frame 冻结帧 | 读取故障发生瞬间传感器快照 | **只读支持** |
| `Mode 0101` | MIL 状态与就绪监控 | 检查故障灯与系统就绪监控状态 | **只读支持** |
| `Mode 0902` | VIN 车辆识别码 | 17 位车辆识别码 | **条件候选**。日本本土版（JDM）使用本土格式，实车通用 Mode 09 可能不返回标准 17 位 VIN。**严格保护隐私，不公开用户车架标识** |

> [!NOTE]
> **燃油消耗与续航里程算法说明**：
> 1. 若实车支持位图包含 `PID 0x5E`，可直接读取 ECU 提供的标准燃油流速（L/h）。
> 2. 若实车不支持 `PID 0x5E`，车机端可通过热线式 MAF 进气流量与理论空燃比进行经典物理模型实时估算：
>    $$\text{Fuel Rate (L/h)} = \frac{\text{MAF (g/s)} \times 3600}{14.7 \times 745}$$
> 3. 剩余续航里程（Distance to Empty）通用 OBD-II 无标准 PID，需车机端结合能耗与油量估算值推算。

### 3.2 第二档：混动扩展待确认（丰田专有增强 UDS 诊断，需特定软件支持与实车验证）

高压动力电池荷电状态（SOC %）、动力电池总压/电流、单体压差、电机温度等**均不属于 SAE Mode 01 通用广播范畴**，属于丰田私有增强诊断。

| 参数项 | 数据含义 | 可读性判定 | 依赖条件与客观限制 |
| :--- | :--- | :---: | :--- |
| **动力电池荷电状态 (SOC %)** | 动力主电池荷电百分比 | **待实车确认** | 需向混动相关 ECU 发起增强查询。依赖诊断软件包含 M15A-FXE 混动协议映射定义。 |
| **高压主电池总电压** | 动力锂电池包总压 | **待实车确认** | 需特定诊断指令，数据帧较长，需适配器支持多帧拼接接收。 |
| **高压主电池充放电电流** | 充放电实时电流 (A) | **待实车确认** | 正值为能量回收充电，负值为放电助力。 |
| **单体电池压差 (Delta V)** | 各电芯/模块最高与最低电压差 | **待实车确认** | 需多帧数据流解析。 |
| **动力电池温度传感器** | 电池包内部各热敏电阻温度 | **待实车确认** | 需私有扩展 PID 支持。 |
| **逆变器 / PCU 温度** | 动力控制单元冷却回路温度 | **待实车确认** | 需私有扩展 PID 支持。 |
| **MG1 / MG2 电机转速与温度** | 发电机与驱动电机的运行工况 | **暂无确凿依据（未知不承诺）** | 2022 款 M15A-FXE 采用新一代混动控制架构，第三方逆向定义尚未完全公开，未经验证实车前不作承诺。 |
| **后桥电机 (1MM, E-Four 专属)**| 后桥感应电机转速与逆变器温度 | **暂无确凿依据（未知不承诺）** | 仅限 MXPH15 车型，缺乏公开逆向诊断定义。 |

> [!WARNING]
> **软件与协议证据边界澄清**：
> 1. **撤回对 Dr. Prius 泛化支持承诺**：经核实 Dr. Prius / Dr. Hybrid 官方支持车型清单（priusapp.com），**2022 款 Yaris Hybrid（XP210 / MXPH10）并未明确列入其官方支持车型**（官方清单主要覆盖老款 Aqua、Prius、Camry 等旧动力总成车型）。因此不能以 Prius 的兼容性直接推定 2022 款 Yaris 支持。
> 2. **私有 ECU 寻址不作绝对断言**：行业常引用的混动 ECU 地址（如 `0x7E2`、`0x7E3`）及 Mode 21/22 指令属于过往丰田车型的第三方逆向经验，**缺乏 2022 款 Yaris 官方维修手册确凿证实**，是否能在实车上透传响应，必须以实车发送测试为准。

### 3.4 本次调研操作原则与安全守则

- **纯只读原则**：本次任务严格界定为**只读数据监测调研**，明确不执行任何写入 ECU、清码（Mode 04）或双向主动测试指令。
- **关于清除故障码 (Mode 04)**：发送清除指令会重置车载监控器的就绪状态（Readiness Monitors），导致系统重新进入学习周期，并抹除故障排查线索。因此在只读遥测中不予执行。
- **关于硬件暗电流与蓄电池保护**：车辆关闭后，适配器由 OBD 常电引脚（Pin 16）直供。因厂商官方未对混动小型 12V 辅助蓄电池在长时间插接下的放电安全给出免责承诺，建议车辆在长期停放（如外出旅行）时主动拔除适配器，避免不必要的暗电流损耗。

## 4. 系统集成可行性与架构设计（Ottocast + Flutter + Tailscale + iOS）

### 4.1 核心网络与通信介质边界辨析
- **OBD 蓝牙链路（端到端点对点无线）**：
  - 本地短距离无线连接（2.4 GHz RFCOMM / BLE GATT），工作于车机与适配器之间（距离约 1 米）。
- **Tailscale 链路（覆盖虚拟局域网 VPN）**：
  - 运行在车机的 WiFi 或 4G 蜂窝网络 TCP/IP 协议栈之上，构建加密隧道连接后端（R9000P）与 iPhone。
- **共存与干扰客观考量**：
  - **逻辑链路完全不同**，但**蓝牙与 WiFi 均工作在 2.4 GHz ISM 频段**。在紧凑车厢空间内，高频并发通信可能产生射频同频干扰，导致偶发性数据包重传或微小延迟。车机端应合理控制 OBD 轮询频率（如 1~2 Hz），避免过度占用无线信道。

### 4.3 轮询调度策略与遥测报文格式

为了防止频繁发送 OBD 请求导致车辆车载总线过载或影响动力系统通信，车机端应采用**分频调度轮询机制**：

1. **高频队列（1 Hz / 每秒 1 次）**：
   - 车速 (`010D`)、发动机转速 (`010C`)、高压电池充放电电流（增强 PID）。
2. **中频队列（0.2 Hz / 每 5 秒 1 次）**：
   - 冷却液水温 (`0105`)、高压电池 SOC %（增强 PID）、发动机负荷 (`0104`)、12V 控制模块电压 (`0142`)。
3. **低频队列（0.05 Hz / 每 20 秒 1 次 或 仅在启动时查询）**：
   - 进气温度 (`010F`)、高压电池包温度、单体电池压差 Delta V、故障码状态 (`0101` / `03`)。
4. **车机上报后端的标准化 JSON 报文设计示例**：
   ```json
   {
     "device_id": "car_p3pro",
     "timestamp": 1728864000,
     "ignition_status": "READY",
     "powertrain": {
       "engine_rpm": 0,
       "vehicle_speed_kph": 38,
       "coolant_temp_c": 84,
       "ev_mode_active": true,
       "instant_fuel_consumption_kml": 0.0
     },
     "hybrid_battery": {
       "soc_percent": 56.5,
       "pack_voltage_v": 178.2,
       "pack_current_a": -8.4,
       "battery_temp_c": 28.0,
       "cell_delta_v": 0.015
     },
     "electrical_12v": {
       "auxiliary_battery_v": 14.1
     },
     "diagnostics": {
       "mil_on": false,
       "dtc_count": 0
     }
   }
   ```

## 5. 最小实车只读验证步骤指南（零风险无侵入操作规程）

当用户在实车上插接适配器准备验证时，应严格遵循以下只读、防亏电操作步骤：

### 步骤 1：适配器物理就位
1. 确保车辆处于完全关闭断电状态（POWER 键指示灯熄灭）。
2. 在驾驶员座椅下方、方向盘左下方仪表台护板内侧找到 16 针白色 DLC3 诊断接口。
3. 将 Veepeak OBDCheck BLE+ 垂直平稳插入，确认适配器上红色 **POWER** 指示灯常亮。

### 步骤 2：车辆进入 READY 就绪态
1. 踩下制动踏板，按下车辆 **POWER** 启动按钮。
2. 确认仪表盘中央亮起绿色 **READY** 指示灯（表明高压接触器吸合，12V DC-DC 转换器启动，车载总线全面唤醒供电）。

### 步骤 3：底层串口与协议握手（AT 初始化序列）
在测试软件中建立与 Veepeak 适配器的 BLE 串口连接，依次发送只读握手指令：
```text
AT Z        --> 复位适配器，响应需包含 "ELM327 v2.2"
AT E0       --> 关闭回显
AT L0       --> 关闭换行符
AT SP 0     --> 设置自动协议搜索（或显式指定 AT SP 6 即 ISO 15765-4 CAN 11/500）
0100        --> 触发与车载 CAN 总线初次同步握手
AT DP       --> 查看实际识别协议，预期输出: "ISO 15765-4 (CAN 11/500)"
```

### 步骤 4：查询实车支持位图（Supported Bitmaps）
依次发送标准位图请求，记录十六进制响应，决定实车具体开放了哪些标准 PID：
```text
0100        --> 查询 PID 01~20 支持位图（如返回 41 00 BE 3F A8 13）
0120        --> 查询 PID 21~40 支持位图
0140        --> 查询 PID 41~60 支持位图
```

### 步骤 5：低频采集验证基础参数
仅发送已在位图中确认支持的基础数据：
```text
0105        --> 读取水温 ECT（计算公式: A - 40）
010C        --> 读取转速 RPM（计算公式: ((A*256)+B)/4）
010D        --> 读取车速 Speed（计算公式: A）
0142        --> 读取控制模块 12V 电压（计算公式: ((A*256)+B)/1000）
```

### 步骤 6：只读故障码扫描
```text
0101        --> 查询 MIL 灯状态与 DTC 数量
03          --> 读取当前存储的排放/动力故障码（无故障时返回 43 00）
07          --> 读取当前待定故障码（Pending DTCs）
### 步骤 6：只读故障码扫描
```text
0101        --> 查询 MIL 灯状态与 DTC 数量
03          --> 读取当前存储的排放/动力故障码（无故障时返回 43 00）
07          --> 读取当前待定故障码（Pending DTCs）
（说明：本次为只读监控，不发送 04 清除故障码，避免重置系统就绪状态）
```

### 步骤 7：12V 辅助蓄电池暗电流防亏电建议
- **常电供电特性**：OBD 接口的 Pin 16 为车辆蓄电池常电，适配器插接后即使车辆熄火也会维持待机供电。
- **使用建议**：由于厂商官方并未对混动车辆长时间插接适配器免除亏电做出保证，建议在车辆预计长期停放（如连续数周不使用）时，主动拔下适配器，保护 12V 辅助蓄电池。

## 7. 关键误判与断言撤回对照表

| 原报告断言 | 事实核对与证据边界校正 | 处置动作 |
| :--- | :--- | :---: |
| **“与车机/协议 100% 兼容”** | 物理引脚与波特率匹配，但实车具体开放哪些 PID 须依实车 ECU 响应位图而定，不可预判 100% 保证。 | **已撤回并校正** |
| **“J-OBD 全部采用 CAN”** | J-OBD 为日本法规统称，老车包含 KWP/私有协议；2008 年 10 月起强制标准 J-OBD II 要求采用 ISO 15765-4 CAN。 | **已校正为 J-OBD II** |
| **“动力电池 48 串三元顶级”** | 官方《主要諸元表》（2022年8月版）仅记载「リチウムイオン電池 4.3Ah」，未记载串联数与材质。 | **已删除未证实断言** |
| **“12V 电池 35~45Ah 在后座椅下方”** | 官方诸元表未印制 12V 蓄电池容量与位置，属于维修手册内容，不应作为诸元表事实引用。 | **已删除未证实数据** |
| **“休眠 15mA 且 1~2 周放电”** | 缺乏针对该批次适配器与实车的精确休眠暗电流官方测试数据，仅做常电拔除建议。 | **已改为客观建议** |
| **“Dr. Prius 完美支持 2022 Yaris”** | Dr. Prius 官方清单并未包含 2022 款 Yaris（MXPH10），不能以老款 Prius 泛化推论。 | **已撤回过度推论** |
| **“完全无标准油耗 PID”** | 标准 SAE Mode 01 包含 `PID 0x5E` (Engine Fuel Rate)，若实车支持可直读，不支持才走 MAF 算法估算。 | **已补充 0x5E 说明** |
| **“PID 0x42 为 12V 蓄电池电压”** | PID 0x42 为 ECU 内部控制芯片供电电压，非蓄电池精确开路端电压。 | **已澄清电压定义** |
| **“车身门锁 CGW 物理隔离”** | 门锁车窗属于车身私有系统，主要在于无公开 SAE Mode 01 PID，不作未证实的网关拓扑断言。 | **已校正为无标准支持** |
| **“蓝牙与 Tailscale 完全互不干扰”** | 逻辑网络层独立，但两者均使用 2.4 GHz ISM 射频频段，车内高频并发存在同频干扰与抖动可能。 | **已补充射频共存说明** |

## 8. 调研结论简明总表

| 评估维度 | 调研结论（基于证据边界） |
| :--- | :--- |
| **设备型号核实** | 确认为 **Veepeak OBDCheck BLE+ (Bluetooth 4.0 Dual-Mode)**，支持 ELM327 v2.2 指令集，物理匹配 2022 Yaris DLC3 接口。 |
| **车机连接性** | Ottocast P3 Pro 系统具备 BLE 特性，但车机厂商可能存在外设定制限制，需实机配对测试。注意 2.4GHz WiFi/蓝牙同频共存。 |
| **第一档：优先可读** | 水温、转速（纯电为0）、车速、进气温、负荷、MAF、ECU电压、DTC 故障码只读。**均需通过实车位图验证**。 |
| **第二档：混动扩展** | 电池 SOC %、高压总压、充放电电流、电池温属于**丰田私有增强 PID，需特定软件支持且待实车测试**；MG1/MG2 电机转速温度**暂无依据，未知不承诺**。 |
| **第三档：车身未知** | 门锁、车窗、灯光、座椅、胎压等**无公开 SAE 标准只读 PID，本方案列为不支持/未知项，不作承诺**。 |
| **安全与保护守则** | 严格限制为**只读监控**，不执行 ECU 写入或 Mode 04 清码；长期停放建议拔除适配器以防暗电流消耗。 |
