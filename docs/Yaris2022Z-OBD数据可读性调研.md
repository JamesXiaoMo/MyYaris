# 日本 2022 款丰田 Yaris Z 混动 OBD-II 数据可读性与车机系统架构调研报告

> **调研对象**：日本本土版 2022 年款丰田 Yaris（ヤリス）Z 混动版（1.5L HYBRID）  
> **硬件配件**：Veepeak OBDCheck BLE+ 蓝牙 4.0 双模 OBD2 扫描器（Amazon ASIN: `B07VP1NHHX`）  
> **宿主系统**：Ottocast P3 Pro 车机盒子（Android 13 / arm64）+ Flutter `car_app`  
> **报告性质**：**只读技术调研与架构可行性论证**（不连接实车、不写 ECU、不清除 DTC、不执行任何主动控制）

## 1. 硬件配件核实与官方规格核对

### 1.1 ASIN 对应产品唯一核实
经 Amazon 日本商品页面（ASIN: `B07VP1NHHX`）与厂商官方技术资料交叉核对，该配件确认为：
- **厂商与产品全称**：**Veepeak OBDCheck BLE+ (Plus) Bluetooth OBD II Scanner**
- **通信模式**：**Bluetooth 4.0 Dual-Mode（双模蓝牙）**
  - **iOS 端**：基于 **Bluetooth Low Energy (BLE / GATT)** 协议通信（无需 Apple MFi 认证芯片，通过 App 内部直接扫描 GATT 服务建立连接，系统原生蓝牙设置菜单中不可直接配对）。
  - **Android 端**：同时支持 **BLE (GATT)** 与 **传统蓝牙 (Bluetooth Classic 3.0 / SPP 串口协议)**。传统蓝牙配对 PIN 码通常为 `1234` 或 `0000`。
- **协议芯片与指令集**：
  - 采用定制 ELM327 兼容固件，完整支持 **ELM327 v1.4 / v2.2** AT 指令集（支持扩展长度缓冲区、自定义 CAN 滤波/屏蔽器设置 `AT SH / AT CRA`、多帧 ISO-TP 数据拼接传输）。
- **支持的车载总线物理协议**：
  - **ISO 15765-4 CAN**（11-bit ID & 29-bit ID, 500 kbaud & 250 kbaud）—— **2022 款 Yaris 实际采用协议**
  - **ISO 14230-4 KWP2000**（5-baud init & fast init）
  - **ISO 9141-2**（老款车型）
  - **SAE J1850 VPW & PWM**（美系老车）
- **电气特性与功耗参数**：
  - 工作电压：`9V ~ 16V`（由车辆 OBD 诊断接口 Pin 16 常电直供）
  - 工作电流：约 `35mA ~ 45mA`
  - 休眠待机电流：约 `15mA`（具备自动休眠与唤醒逻辑，但非物理断电）
  - 尺寸与重量：`4.1 × 5.0 × 2.2 cm`，约 `45g`

### 1.2 日本 J-OBD / J-OBD II 兼容性确认
- 日本自 2008 年 10 月起对本土乘用车强制实行 **J-OBD II** 诊断法规，全面采纳 ISO 15765-4 CAN 诊断标准。
- 2022 款日本本土版 Yaris（XP210 系）OBD 物理接口（DLC3，位于驾驶席左下方膝部护板内侧）Pin 6 (CAN-H)、Pin 14 (CAN-L)、Pin 4/5 (地线)、Pin 16 (12V 电源) 完全遵循 SAE J1962 / ISO 15765 标准，**与 Veepeak OBDCheck BLE+ 硬件与协议层 100% 物理兼容**。

### 1.3 厂商官方兼容性警告与 Ottocast P3 Pro 特殊性核查
- **Veepeak 官方提示**：官方文档明确标注 *“Android car stereos/head units are generally not recommended or compatible”*（通常不推荐或不保证兼容通用安卓车机大屏导航）。
  - **根因**：市场上大量低成本联发科/展讯方案安卓后装车机剥离了标准 Android BLE 协议栈，或蓝牙芯片被电话免提（HFP/A2DP）独占，无法发起通用 SPP 或 BLE 扫描。
- **Ottocast P3 Pro 实机技术核验（只读）**：
  - 本项目使用的 Ottocast P3 Pro 运行高通骁龙 6125/665 平台（Android 13 / arm64）。
  - 实机只读核查确认其系统服务清单明确具备：
    ```
    feature: android.hardware.bluetooth
    feature: android.hardware.bluetooth_le
    ```
  - 底层运行 Qualcomm Bluetooth Daemon (`QCOM-BTD-a7a4`)，完整支持 BLE Central 外设连接。
  - **工程对策**：在 Flutter `car_app` 中应优先选用 **BLE (Bluetooth Low Energy) GATT** 模式连接（使用 `flutter_blue_plus`），避开系统层 PIN 配对限制与车机免提蓝牙通道抢占。

## 3. 可读取信息分类矩阵与实车约束

在 OBD-II 诊断体系中，数据分为**标准 SAE J1979 公开通用广播**与**丰田专有增强 UDS 诊断**。任何标准 PID 的实际可用性都**必须以实车 ECU 返回的 PID 支持位图（Supported Bitmap）为准**，不能仅凭理论断定。

### 3.1 类别一：标准 SAE J1979 OBD-II Mode 01 参数支持表（发动机/基础排放）

标准 OBD-II（Mode 01）通过标准 11 位 CAN ID `0x7DF` 广播或 `0x7E0`（发动机 ECM）请求。

| PID 编号 | 参数名称 | 数据含义与实车行为 | 混动工况特殊性与可用性判定 |
| :---: | :--- | :--- | :--- |
| `0x00` | Supported PIDs [01-20] | 支持位图 1~20 | **必须优先查询**。决定后续 01~20 PID 是否有效 |
| `0x0C` | Engine RPM | 发动机实际转速 (rpm) | **基本支持**。EV 纯电滑行/停机时读数瞬时为 `0` |
| `0x0D` | Vehicle Speed | 车速 (km/h) | **基本支持**。由轮速传感器/混动驱动桥计算，全程有效 |
| `0x05` | Engine Coolant Temp (ECT) | 发动机冷却水温 (°C) | **基本支持**。冷车启动暖机状态监测的关键指标 |
| `0x0F` | Intake Air Temp (IAT) | 进气温度 (°C) | **基本支持**。MAF 进气口传感器温度 |
| `0x11` | Throttle Position | 节气门开度 (%) | **基本支持**。电子节气门实际开度；纯电停机时维持怠速位或关断 |
| `0x04` | Calculated Engine Load | 计算发动机负荷 (%) | **基本支持**。纯电驱动停机时为 `0%` |
| `0x06` | Short Term Fuel Trim (STFT) | 短期燃油修正 (%) | **条件支持**。仅在发动机点火并进入闭环 (Closed Loop) 时有效 |
| `0x07` | Long Term Fuel Trim (LTFT) | 长期燃油修正 (%) | **条件支持**。同上 |
| `0x10` | Mass Air Flow (MAF) | 空气质量流量 (g/s) | **基本支持**。M15A-FXE 标配热线式 MAF；纯电时为 `0 g/s` |
| `0x0B` | Intake Manifold Absolute Pressure | 进气歧管绝对压力 (MAP) | **条件支持**（丰田通常以 MAF 为主，MAP 需看位图是否开启） |
| `0x14` | O2 Sensor Voltage | 前后氧传感器 / 空燃比 | **条件支持**。发动机点火闭环状态下有效 |
| `0x1F` | Run Time Since Engine Start | 发动机启动运行时间 (秒) | **条件支持**。混动频繁启停，部分固件记录单次点火时长 |
| `0x20` | Supported PIDs [21-40] | 支持位图 21~40 | 决定 21~40 PID 是否有效 |
| `0x40` | Supported PIDs [41-60] | 支持位图 41~60 | 决定 41~60 PID 是否有效 |
| `0x42` | Control Module Voltage | 控制模块供电电压 (V) | **基本支持**。反映车机 12V 低压电网实际工作电压（非动力高压） |
| `0x46` | Ambient Air Temp | 车外环境温度 (°C) | **条件支持**。需仪表/空调模块向发动机总线广播该 PID |

### 3.2 类别二：燃油量、油耗与续航里程（ECU 直接 vs 算法估算）

许多用户误以为 OBD 接口插上就能直接读出“剩余油量升数”与“瞬时百公里油耗”，但在丰田混动上必须严格区分来源：

1. **燃油箱剩余液位（Fuel Tank Level, Mode 01 PID 0x2F）**：
   - **实车现状**：**大概率不支持（NO DATA）或条件支持**。
   - **技术根因**：日本本土版丰田车型的油箱浮子传感器信号直接硬线连接至**组合仪表 ECU（Combination Meter, CAN ID 0x7C0）**或中央网关，并未路由至发动机 ECM（0x7E0）。因此向发动机发送通用 `012F` 请求通常无响应，必须通过专有 UDS 诊断指令向仪表 ECU 发起请求。
2. **瞬时油耗 / 百公里油耗（L/100km 或 km/L）**：
   - **实车现状**：**ECU 无直接标准只读 PID，必须由车机应用端实时算法估算**。
   - **算法公式**：
     $$\text{Fuel Rate (L/h)} = \frac{\text{MAF (g/s)} \times 3600}{\text{Air-Fuel Ratio (14.7)} \times \text{Gasoline Density (745 g/L)}}$$
     $$\text{Instant Economy (km/L)} = \frac{\text{Vehicle Speed (km/h)}}{\text{Fuel Rate (L/h)}}$$
   - **混动特性**：在纯电滑行或发动机停机时，$\text{MAF} = 0$，瞬时油耗立即归零（$\infty \text{ km/L}$ 或 $0 \text{ L/h}$），能极为精准地反映混动节油特性。
3. **剩余续航里程（Distance to Empty, DTE）**：
   - **实车现状**：**通用 SAE OBD-II 无此 PID**。仪表盘上的“航続可能距離”属于仪表内部私有算法，普通 OBD2 工具无法读取，需车机端根据剩余油量估算值与历史平均能耗本地推算。

### 3.3 类别三：丰田混动系统专有增强参数（THS II 扩展 PIDs）

混动车主最关心的**高压电池 SOC、动力电池电压/电流/温度、电机逆变器状态**，**均不属于 SAE Mode 01 通用范畴**，属于丰田私有 UDS / ISO 14229 增强诊断（Mode 21 / Mode 22）。

必须向对应 ECU 地址寻址：
- **混动车辆控制系统 (HV ECU)**：CAN ID `0x7E2`（响应 `0x7EA`）
- **电池智能监控单元 (Battery Smart Unit)**：CAN ID `0x7E3`（响应 `0x7EB`）

| 参数类别 | 具体参数项 | 能否读取判定 | 约束与依赖条件说明 |
| :--- | :--- | :---: | :--- |
| **高压主电池 (HV)** | **主电池荷电状态 (SOC %)** | **条件可读** | 丰田专有 PID（通常在 40%~80% 控制死区内波动）。依赖上位机软件包含 M15A-FXE 混动协议定义。 |
| **高压主电池 (HV)** | **电池总电压 (Pack Voltage, ~177V)** | **条件可读** | 48 串锂电池总压。需向 Battery ECU 发起增强查询。 |
| **高压主电池 (HV)** | **电池充放电电流 (Pack Current, A)** | **条件可读** | 正值为能量回收充电，负值为纯电/助力放电。 |
| **高压主电池 (HV)** | **单体/模块电压与压差 (Delta V)** | **条件可读** | 锂电池各模块电压与最大/最小单体压差。数据帧长，需适配器支持多帧接收。 |
| **高压主电池 (HV)** | **电池包温度传感器 (Temp 1~3, 入口温)** | **条件可读** | 电池箱内部热敏电阻采样值。 |
| **混动电机与电控** | **逆变器/增压转换器温度 (°C)** | **条件可读** | PCU（动力控制单元）水冷回路与 IGBT 温度。 |
| **混动电机与电控** | **MG1（发电机）转速 / 温度** | **暂无确凿证据（未知不承诺）** | 在老款 Prius (2ZR) 上已知，但 2022 款 M15A-FXE 采用新 UDS 地址，第三方定义可能滞后。 |
| **混动电机与电控** | **MG2（驱动电机 1NM）转速 / 扭矩 / 温度** | **暂无确凿证据（未知不承诺）** | 同上，未经验证实车私有 PID 映射表前不作承诺。 |
| **混动电机与电控** | **后轴电机 (1MM, E-Four 专属) 转速/温度** | **条件可读 / 暂无证据** | 仅限 MXPH15 车型，需后桥逆变器专属诊断地址，缺乏公开规范。 |
| **制动与动能回收** | **回生制动要求扭矩 vs 油压制动分配** | **条件可读** | 属于防滑控制系统（Skid Control / ABS ECU, 0x7B0），通用适配器轮询易引起总线拥堵。 |

> [!IMPORTANT]
> **对 Veepeak 硬件与软件授权的明确约束**：
> 1. Veepeak OBDCheck BLE+ 本身**仅作为透传网关**，只要发送正确的 AT 切换报头指令（如 `AT SH 7E2`、`AT CRA 7EA`），它具备处理 11-bit CAN 多帧通信的能力。
> 2. 但**通用免费 OBD 软件（如未导入私有配置的通用软件）绝对读不出上述混动数据**。
> 3. 必须依赖第三方已逆向破解的软件数据库（如 *Car Scanner ELM OBD2* 专门维护的「Toyota Yaris / Hybrid 2020+」配置、*Dr. Prius* 专门针对丰田混动的授权库、或丰田原厂 Techstream GTS+ 诊断仪）。

### 3.4 类别四：车身、舒适与底盘系统（门锁/车窗/座椅/灯光/胎压/转向/里程）

| 功能系统 | 具体数据项 | 能否通过 OBD 适配器读取 | 现状与底层限制分析 |
| :--- | :--- | :---: | :--- |
| **车身门锁** | 4 门锁止状态、尾门开闭 | **不支持 / 极高难度** | 属于 Body ECU（车身总线）。位于中央网关（CGW）后方独立的 Body CAN，不对 OBD 接口主动广播，无公开 SAE 标准。 |
| **车窗与天窗** | 车窗升降位置、开闭状态 | **不支持 / 极高难度** | 同上，属于车门微控制器 LIN 总线子网。 |
| **座椅与安全带** | 座椅加热状态、乘客占用传感器 | **不支持** | 属于 SRS / 车身舒适总线，涉密且安全等级高，网关防火墙默认阻断。 |
| **外部与内部灯光** | 大灯、示宽灯、转向灯、远光状态 | **不支持** | 属于照明控制子网，无公开只读诊断服务。 |
| **胎压监测 (TPMS)** | 4 轮单独胎压 (kPa/bar) 与胎温 | **条件支持 / 极高难度** | 日本本土版 Yaris 部分采用间接胎压（基于轮速差计算，无物理压力传感器）或胎压直接传感器。即使有传感器，也需向 TPMS ECU（0x7D0）查询。 |
| **转向系统** | 方向盘转角、转向力矩 | **条件支持** | 属于 EPS 电动助力转向 ECU（0x730），需私有 UDS 协议支持。 |
| **累计里程 (Odometer)**| 总行驶里程 (ODO, km) | **条件支持** | 标准 Mode 01 PID 0xA6 极少被 JDM 车型实现；通常存储在仪表盘 ECU（0x7C0），需私有查询。 |

> [!NOTE]
> **“未知不是不支持”**：在丰田工厂研发与 4S 店 Techstream 诊断仪视角下，上述车身数据全都在专用 CAN 总线上流通；但在**通用消费级 OBD2 适配器 + 只读模式**视角下，缺乏专有私有协议逆向与网关穿透授权，常规手段无法稳定采集。

### 3.5 类别五：车辆识别码 (VIN) 与故障码服务

1. **车辆识别码 (VIN, Mode 09 PID 02)**：
   - **实车现状**：**很可能返回 `NO DATA` 或空格**。
   - **技术根因**：日本本土版车辆（JDM）法规并不强制要求在 ECU 内部写入 17 位的欧美标准 VIN 码，而是使用日本本土的**車台番号（如 `MXPH10-0123456`，长度仅 12~14 位）**。JDM 丰田车型的发动机 ECM 收到 SAE Mode 09 PID 02 时，往往因为格式不符直接不响应。
   - **隐私保护准则**：**无论是否读出，严禁在日志、文档、界面或网络通信中公开泄露用户的真实车台番号或 VIN 码**。
2. **故障码 (DTC) 与冻结帧**：
   - **Mode 03（已存储故障码）**：**完全只读支持**。可安全读取排放与动力系统故障码（如混动高压电池故障码 `P0A80`、发动机失火 `P0300` 等）。
   - **Mode 07（待定故障码）**：**完全只读支持**。
   - **Mode 02（冻结帧数据）**：**完全只读支持**。读取触发故障发生瞬间的冷却水温、车速、发动机负荷快照。
   - **Mode 01 PID 01（MIL 故障灯状态与就绪状态 Readiness Monitors）**：**完全只读支持**。

### 3.6 严格红线：主动控制、清码与 ECU 刷写的风险警示

- **绝对禁止执行 Mode 04（Clear/Reset Diagnostic Trouble Codes）**：
  - 清除故障码会同时将 ECU 内所有排放与系统就绪监控（Readiness Monitors）全部重置为“未就绪”状态，可能导致日本车检（車検）无法通过，且会消除关键故障排查证据。
- **绝对禁止执行双向主动控制（Mode 2F / Mode 30 Input/Output Control）**：
  - 如强行触发燃油泵测试、风扇强制最高速运转、EV 模式强制切断等，驻车或行驶中极易引发混动系统报错（Master Warning、检查混动系统报警灯亮起）。
- **绝对禁止涉及 ECU 刷写与网关绕过**：
  - 本项目界定为**纯只读数据采集**，严禁尝试任何写入、标定修改或安全网关暴力破解。

## 4. 系统集成可行性与架构设计（Ottocast + Flutter + Tailscale + iOS）

### 4.1 核心网络与通信介质边界辨析
- **OBD 蓝牙链路（端到端点对点无线）**：
  - 属于本地物理层/链路层无线连接（2.4 GHz RFCOMM / BLE GATT）。
  - 连接在**车机盒子（Ottocast P3 Pro）**与**插在仪表盘下方的 Veepeak 适配器**之间，通信距离约 1 米。
- **Tailscale 链路（覆盖虚拟局域网 VPN）**：
  - 运行在车机的 WiFi / 4G 蜂窝网络 TCP/IP 协议栈之上，构建加密点对点隧道连接至后端主机（R9000P）与 iPhone。
- **关键结论**：**OBD 蓝牙连接与 Tailscale 网络完全独立解耦、互不冲突**。蓝牙链路的数据读取完全不会干扰 Tailscale 的内网穿透或数据推送。

### 4.3 轮询调度策略与遥测报文格式

为了防止频繁发送 OBD 请求导致车辆车载总线过载或影响动力系统通信，车机端应采用**分频调度轮询机制**：

1. **高频队列（1 Hz / 每秒 1 次）**：
   - 车速 (`010D`)、发动机转速 (`010C`)、高压电池充放电电流（增强 PID）。
2. **中频队列（0.2 Hz / 每 5 秒 1 次）**：
   - 冷却液水温 (`0105`)、高压电池 SOC %（增强 PID）、发动机负荷 (`0104`)、12V 控制模块电压 (`0142`)。
3. **低频队列（0.05 Hz / 每 20 秒 1 次 或 仅在启动时查询）**：
   - 进气温度 (`010F`)、高压电池包温度、单体电池压差 Delta V、故障码状态 (`0101` / `03`)。
4. **车机上报后端的标准化 JSON 报文设计示例**：

## 5. 最小实车只读验证步骤指南（零风险无侵入操作规程）

当用户在实车上插接适配器准备验证时，应严格遵循以下只读、防亏电操作步骤：

### 步骤 1：适配器物理就位
1. 确保车辆处于完全关闭断电状态（POWER 键指示灯熄灭）。
2. 在驾驶员座椅下方、方向盘左下方仪表台护板内侧找到 16 针白色 DLC3 诊断接口。
3. 将 Veepeak OBDCheck BLE+ 垂直平稳插入，确认适配器上红色 **POWER** 指示灯常亮。

### 步骤 2：车辆进入 READY 就绪态
1. 踩下制动踏板，按下车辆 **POWER** 启动按钮。
2. 确认仪表盘中央亮起绿色 **READY** 指示灯（表明高压接触器吸合，12V DC-DC 转换器启动，车载总线全面唤醒供电）。

### 步骤 3：底层串口与协议握手（AT 初始化序列）
在测试软件中建立与 Veepeak 适配器的 BLE 串口连接，依次发送只读握手指令：
```text
AT Z        --> 复位适配器，响应需包含 "ELM327 v2.2"
AT E0       --> 关闭回显
AT L0       --> 关闭换行符
AT SP 0     --> 设置自动协议搜索（或显式指定 AT SP 6 即 ISO 15765-4 CAN 11/500）
0100        --> 触发与车载 CAN 总线初次同步握手
AT DP       --> 查看实际识别协议，预期输出: "ISO 15765-4 (CAN 11/500)"
```

### 步骤 4：查询实车支持位图（Supported Bitmaps）
依次发送标准位图请求，记录十六进制响应，决定实车具体开放了哪些标准 PID：
```text
0100        --> 查询 PID 01~20 支持位图（如返回 41 00 BE 3F A8 13）
0120        --> 查询 PID 21~40 支持位图
0140        --> 查询 PID 41~60 支持位图
```

### 步骤 5：低频采集验证基础参数
仅发送已在位图中确认支持的基础数据：
```text
0105        --> 读取水温 ECT（计算公式: A - 40）
010C        --> 读取转速 RPM（计算公式: ((A*256)+B)/4）
010D        --> 读取车速 Speed（计算公式: A）
0142        --> 读取控制模块 12V 电压（计算公式: ((A*256)+B)/1000）
```

### 步骤 6：只读故障码扫描
```text
0101        --> 查询 MIL 灯状态与 DTC 数量
03          --> 读取当前存储的排放/动力故障码（无故障时返回 43 00）
07          --> 读取当前待定故障码（Pending DTCs）
（*** 严禁发送 04 ***）
```

### 步骤 7：重要安全守则：12V 辅助蓄电池防亏电注意事项
- **混动车电瓶特性**：Yaris 混动的 12V 辅助蓄电池（安装在后排座椅下方）仅用于唤醒行车电脑与吸合高压继电器，容量相对纯燃油车较小（约 35~45 Ah）。
- **静态休眠电流**：Veepeak OBDCheck BLE+ 在熄火后进入休眠仍会消耗约 15mA 静态电流。
- **使用建议**：日常频繁通勤使用无妨；但**若车辆预计连续停放超过 1~2 周不启动，强烈建议将 OBD 适配器从插座上拔下**，彻底避免 12V 蓄电池亏电导致车辆无法进入 READY 状态。

## 7. 调研结论总结

| 评估维度 | 调研结论 |
| :--- | :--- |
| **设备型号核实** | 确认为 **Veepeak OBDCheck BLE+ (Bluetooth 4.0 Dual-Mode)**，支持 ELM327 v2.2 指令集与 ISO 15765-4 CAN，完全兼容日本 J-OBD II 规范。 |
| **车机兼容性** | Ottocast P3 Pro 实机具备 Qualcomm BLE 协议栈；Flutter 可通过 BLE GATT 服务实现无 PIN 码稳定通信。 |
| **标准通用数据** | 冷却水温、车速、发动机转速、进气温、负荷、12V 电压**可稳定读取**；瞬时油耗通过算法精准估算；油箱液位 PID 0x2F 大概率不支持。 |
| **混动扩展数据** | 电池 SOC、高压总压、充放电电流、单体压差、电池温度属于**条件可读**（高度依赖上位机内置丰田私有协议解析）；MG1/MG2 专属电机数据**暂无确凿逆向依据，不作无条件承诺**。 |
| **车身/舒适控制** | 门锁、车窗、灯光、座椅、胎压因网关物理隔离且无公开 SAE 规范，常规 OBD2 工具**不支持读取**。 |
| **行车安全原则** | 严格执行**只读监控**，杜绝 Mode 04 清码与主动控制；长期停放（>2周）需拔除以防 12V 电瓶暗电流损耗。 |
