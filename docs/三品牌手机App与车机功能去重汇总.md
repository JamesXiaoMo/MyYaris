## 0. 结论速览

1. **三家手机 App 都不是「遥控器」，而是「服务入口 + 权限管理台」**：稳定具备的能力集中在四块——车辆状态与远程车控、数字钥匙与权限分享、充电补能、售后与商城社区。**媒体播控、应用安装、辅助驾驶接管几乎全部留在车机侧**，App 主要做「发目的地」「看状态」「管授权」。
2. **真正的功能分水岭是「权限颗粒度」而不是「远程开空调」**：远程解闭锁/空调/尾门三家都有；差异在于**授权对象、名额上限、被授权人可用与不可用的功能**。官方明确例：理想「家人共享」L 系列上限 5 人、理想 ONE 上限 2 人，且**家庭成员无法使用哨兵模式、不支持查看车辆位置与驻车照片**；蔚来授权为「共同用车人 1 名 + 被授权人最多 9 名」，且**被授权人行驶中，停止授权要等其停车锁车后才生效**；小米官方隐私政策写明授权项包含「数字钥匙状态、远程控制权限、定位权限、米家控车开关、小爱控车开关」，并支持「常用人」标签。
3. **真正的车型差异比品牌差异更值得警惕**：在蔚来官方手册中，**前备箱 / 电动遮阳帘 / 车载冰箱的远程控制只见于全新 ES8、ET9 等车型的章节**；ET5T 手册车控清单未列这些项，按本轮资料只能记为**资料未覆盖/未知**。ET9 章节另有**后排行政屏**跨屏同播与手机镜像。理想同品牌内也可见分档：**L7/L8/L9 的 Pro 版官方手册目录未包含「城市智能驾驶 / 全场景辅助驾驶 / 记忆泊车 / 车位到车位」，设置路径写作「AD Pro」而非「AD Max」**（目录缺失同样属资料覆盖问题，不等同于官方声明不支持）。因此本文不对任何品牌做「全系具备某功能」的泛化。
4. **营销名不同、功能同构的部分（本文已归并）**：场景自动化＝小米「超级任务 / HyperTask」、理想「任务大师」、蔚来「快捷场景 / 乐道智慧场景」；语音助手＝超级小爱 / 理想同学 + Mind GPT / NOMI（乐道为小乐、firefly 为 lumo）；直线移车＝小米「直线移车辅助」、理想「直线召唤」、蔚来「车辆召唤」。
5. **对 MyYaris 的现实结论（不做一句话全盘否定）**：当前架构（Flutter Android 车机 + Flutter iOS 占位页 + Linux FastAPI/SQLite + Tailscale，无 CAN、无原厂钥匙接口）需区分三种情形——①**纯软件、可直接借鉴**：导航发送与状态回执、任务队列与幂等、媒体会话播控、连接诊断页、权限与角色模型；②**软件可行，但依赖接入或技术评估**：手机远程媒体控制、车机状态上报、语音入口、场景自动化、行程与能耗（**能耗/里程类数据必须有 OBD/CAN 或可信数据源，不能靠「后端扩展」凭空得到**）；③**受原厂接口或授权限制、当前无可行接入路径**：远程车控、数字钥匙与分享、哨兵与远程车外实况、充电与换电、整车 OTA、ADAS 入口、售后权益。其中**车家互联、CarPlay、手机应用桌面化、投屏**属「技术条件待评估」——它们不依赖整车总线，但取决于设备/系统侧能力（Android 车机盒子是否开放对应通道、iOS 侧是否提供相应框架、目标 App 是否支持被调起），**不应一概判为无法复刻**，也不应作为已可实现的承诺。

1. **远程车控 ≠ 车机本地控制**：第 2 章为手机 App 能力，第 3 章为中控能力，条件不同（远程多要求 P 挡、门全关、车辆联网）。
2. **ADAS 硬件能力 ≠ App 能力**：本节只记录 App/中控里的「入口与设置」（第 3.8 节），不把「城市智驾」「高速 NOA」本身当作 App 功能。
3. **官方截屏可见 ≠ 官方文字确认**：小米的「遥控泊车辅助 / 直线移车辅助 / 前备箱 / 后备箱 / 鸣笛闪灯」目前只能从官方 App Store 截屏看到；官方隐私政策对车控采用兜底表述「具体以本应用车辆控制页面展示的功能为准」，即官方**未给出车控功能的封闭清单**——这类条目本文一律标为「仅官方截屏可见」或「未知」。
4. **品牌手机专属 ≠ App 通用能力**：蔚来的 NIO Link 跨端、位置与导航流转、沉浸声、媒体接力均**需要 NIO Phone**；小米的手车互联/语音控车需小米手机与同一小米账号。不能算作通用 App 能力。
5. **「官方没写」不等于「不支持」**：蔚来的 CarPlay/HiCar/CarLife、理想的 CarPlay 在官方手册与官网中零命中，本文记为「未知」。
6. **「AD Pro 有」不等于「AD Max 有」，反之亦然**：理想官方手册目录显示 Pro 与 Max 的智驾/泊车能力集不同（Pro 目录无城市智驾、全场景辅助驾驶、记忆泊车、车位到车位），但两者**都有**智能泊车、遥控泊车（离车泊入）、直线召唤、高速智能驾驶；此外 AD Pro 与 AD Max 的高速智能驾驶激活方式也不同。汇总时不应混用。

## 8. 对 MyYaris 的借鉴分档（建议，非已实现）

> 以下全部为**调研建议**，不代表 MyYaris 已实现。判断依据来自当前仓库现状：`car_app/`（Flutter Android，含 `MainActivity` 的导航/媒体 MethodChannel、`KeepAliveService`、`MediaControlNotificationListenerService`、`BootReceiver`、`NavTransitionActivity`、长轮询 `TaskPollerService`、`SharedPreferences` 存储）、`ios_app/`（Flutter iOS 占位页，仅 `main.dart`）、`backend/`（FastAPI + SQLAlchemy：`/health`、`/destinations`、`/tasks/{id}`、`/devices/{id}/tasks/next`、`/tasks/{id}/ack`、`/voice`，预共享 Token 鉴权），部署依赖 Tailscale + HTTPS。项目**未接入 CAN/LIN 与任何原厂钥匙/账号接口**。

### 第 1 档：可直接借鉴的软件功能（不依赖原厂硬件与账号）

1. **导航发送 + 状态跟踪**：三家都把「发送目的地」作为手机侧高频入口并回显状态。MyYaris 已有 `POST /destinations` 与 `launch_requested` 语义，建议借鉴其状态分级文案，继续保持不承诺「已开始导航」。
2. **任务队列与幂等/过期/取代**：理想「设置升级时间」、蔚来「预约升级」本质是「定时任务 + 到点条件校验」，与后端 `queued → received → launch_requested` 状态机同构；后端已有 `superseded_by`、`expires_at`、`delivery_attempts`，可继续沿用。
3. **媒体播控 UI 与会话读取**：车机端已通过 MediaSession / NotificationListener 读取曲目与播放状态并提供 play/pause/next/prev/自定义 action。可借鉴三家共有的「当前曲目卡片 + 大触控区 + 来源标识 + 歌词」布局。
4. **场景自动化（本机条件触发）**：三家都是「条件 + 动作」模型，可在**车机本地**先做一版（例如：连接指定 WiFi / 收到某任务 → 打开导航或切换媒体源），不涉及原厂硬件。
5. **连接与诊断页**：三家都有「连接/授权/网络」类状态入口。车机已有 `connection_debug_page.dart`，可借鉴其信息层级（链路状态、最近心跳、失败原因）。
6. **最近目的地 / 历史快捷重发**：后端已持久化历史任务，可做成列表复用；对应三家的收藏点与历史导航思路。
7. **权限与角色模型（仅本系统内）**：可借鉴三家的权限颗粒度设计（授权项列表、常用人、被授权人可见范围），用于后端 Token 角色划分（当前只有 car/phone/admin 预共享 Token）。
8. **隐私边界与「不承诺」的文档习惯**：小米代客模式屏蔽位置与影像、蔚来寻车照片脱敏、云端不存哨兵视频等，提示自用项目应在文档与界面中明确数据保留与可见范围。
9. **按「配置/车型」写清能力边界，而不是按品牌**：理想官方手册用目录级差异区分 AD Pro 与 AD Max 能力集，蔚来官方手册反复声明「不同配置或车型的 App 车控功能可能存在差异」。自用项目即使只有一台车，也建议在文档与设置页标注「本能力仅在某配置/版本可用」。

### 第 2 档：需后端扩展才能实现（软件可行，但当前后端缺接口/能力）

1. **手机端远程媒体控制**：需新增后端接口（例如 `POST /media/command`）与车机命令下发通道（复用长轮询或新增 SSE/WebSocket），并处理命令幂等、超时与车机离线语义。当前 `music_service.dart` 仅为本地原型，**手机到后端的远程音乐调度接口尚未实现**。
2. **车机端主动状态上报**（媒体、网络、任务、播放进度等软件状态）：三家的状态卡片都依赖车端上报；需要新接口与状态存储（可扩展 `Device.last_seen_at` 为多字段状态表）。
3. **弱网/离线补投与近场直连**：理想以蓝牙兜底、蔚来蓝牙钥匙 30–70 米，说明近场链路重要；若要模拟「车边直发」，需要蓝牙或局域网直连通道（当前只有 Tailscale 网络通道）。
4. **语音入口闭环**：后端已有 `/voice`（ASR/NLP provider 可插拔），但 `ASR_PROVIDER=none`、`NLP_PROVIDER=none`，**未接真实供应商**；要借鉴三家语音体验需接入并定义「语音 → 地点候选 → 确认 → 任务」链路。
5. **多用户 / 多车权限关系**：后端 `Device` 支持多设备，但缺「用户-车辆-权限」关系表，无法实现「家人共享后谁有什么权限」。
6. **推送通知**：三家的异常/充电/任务提醒依赖系统推送；MyYaris 需新增推送通道（APNs/FCM 或本地轮询提示）。
7. **行程与能耗展示**：后端可以补接口，但**数据本身不能靠后端凭空产生**——必须有 OBD/CAN 读取、整车数据源，或可信的替代数据源（如充电桩计量、充电订单、用户手工录入的里程与费用）。本车当前不具备这些数据源，因此该项在数据源未定前只能做「手工/充电记录」级别，不能宣称等效于原厂能耗曲线。
8. **设置同步与场景分享**：可借鉴「配置云端存储 + 车联网下发」（小米超级任务）或「分享码 / 口令分享」（理想任务分享、乐道智慧场景口令），但要先有账号与配置存储。

### 第 3 档：软件层能力，但技术条件待评估（不宜直接判「无法复刻」）

1. **CarPlay / 手机投屏接入**：不依赖整车总线，但取决于车机盒子（Android 13）是否具备厂商授权与相应通道、iOS 侧是否提供可用框架；**需要实机验证，不宜先验判死，也不宜当作已可实现**。
2. **手机应用 Pin 到车机桌面 / 应用流式使用**：取决于 Android 侧多窗口、虚拟显示与投屏/串流能力（如系统是否允许跨应用画面投送与输入回传），属可评估项。
3. **车家互联（车内控制家居）**：目标侧（如米家等智能家居平台）是否开放第三方云端 API 与授权流程未知，需按其开放平台政策评估；不依赖汽车总线。
4. **车载小程序 / 轻应用容器**：属软件容器与合规接入问题，可行性取决于目标平台与小程序来源授权。
5. **蓝牙/LAN 近场直连**：车机与手机都具备蓝牙与局域网硬件，主要是权限、配对与稳定性工程问题，而非原厂授权问题。

### 第 4 档：依赖原厂硬件/账号，当前无可行的自建接入路径

1. **远程解闭锁、车窗、前备箱/尾门、空调、座椅加热通风、寻车闪灯鸣笛、悬架高度调节**：需原厂 T-Box/车云接口或 CAN/LIN 车身控制权限。MyYaris 运行于外挂 Android 车机盒子，**严禁承诺此类整车控制**。
2. **数字钥匙（蓝牙/NFC/UWB）与钥匙分享、授权用车、访客模式、服务授权**：依赖原厂钥匙系统与安全芯片。
3. **哨兵/守卫模式、远程车外实况、行车记录仪紧急录像、驻车拍照上传**：依赖原厂环视摄像头、存储与车云上传链路。
4. **充电与能源管理（充电上限、电池保温/预热、预约充电、家充桩管理、即插即充、换电下单与 PSAP、一键加电）**：依赖原厂充电协议、充电网络与账号体系。
5. **OTA 整车升级（含智驾/动力/悬架/灯光）**：依赖原厂整车刷写能力。
6. **辅助驾驶相关的一切控制入口（VLA 指挥、NOA 开关、泊车辅助、语音控车/泊车、灯光联动）**：依赖原厂 ADAS 硬件与底盘执行器。
7. **换电、BaaS、官方二手车、租车、保险与无忧服务**：属品牌商业体系，与本项目无关。
