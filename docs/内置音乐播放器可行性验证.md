## 1. 验证背景与核心结论

### 1.1 背景说明
官方网易云音乐车载客户端存在以下工程限制：
1. **无公网受控开放 API**：无法由 iPhone 远程精准下发播放指定歌曲、歌单、切换循环模式。
2. **MediaSession 限制**：其 MediaSession 仅暴露单向回调及受限按键（仅支持上一曲、下一曲、播放/暂停、seek），无法动态控制或读取播放列表与完整播放状态。
3. **车机系统偶发网络/DNS 抖动**：当外置车机盒子 DNS 发生异常时，在线音乐客户端整机瘫痪且界面卡顿。

为实现「iPhone 客户端远程自由选歌、换歌、循环模式切换与低延迟播控」，需在 `MyYaris` 车机 App 内置一套轻量、稳定、低功耗的本地音频播放器核心。

### 1.2 核心结论：完全可行（已真机跑通）
- **核心组件选型**：基于 `just_audio: ^0.10.6` + `audio_session: ^0.2.4` + `audio_service: ^0.18.19`（底层基于 Google AndroidX Media3 / ExoPlayer 1.4.1）。
- **音频解码验证**：已内置 3 段合成短音频（WAV 无损采样，包含高频钟声、低频律动、氛围和弦），**100% 离线解码**，与公网 DNS/TLS 完全解耦。
- **播控与模式实测**：上一曲、下一曲、播放/暂停、进度 Seek、三种循环模式循环切换（列表循环 / 单曲循环 / 顺序播放）、随机播放开关全部实测通过。
- **系统音频焦点与共存**：配置为 `AudioSessionConfiguration.music()`，输出至硬件音频通道 `DeviceId:3`，与系统导航提示音共存顺畅。
- **系统资源开销**：Debug 构建下总 PSS 约 380MB（Native Heap 57MB，Java Heap 17MB），播放期间 CPU 占用极低（< 3%），退出到桌面后台后音乐持续播放、进程不被系统查杀。

## 4. 架构设计：两层解耦架构

为保证系统的可靠性，**严格区分「音频播放引擎」与「网易云曲库接入」**，二者通过统一的元数据契约解耦：

```mermaid
flowchart TD
    subgraph iPhoneClient ["iPhone 客户端 (MyYaris iOS)"]
        UI["iPhone UI (播放控制/曲库检索/歌单)"]
    end

    subgraph CloudBackend ["Ubuntu 云端中继 (FastAPI)"]
        API_Route["/api/car/music 路由"]
        NeteaseProxy["NeteaseCloudMusicApi 代理服务 (Docker)"]
        StateHub["车机播控状态广播 Hub (WebSocket / Polling)"]
    end

    subgraph CarMachine ["Ottocast P3 Pro 车机 (MyYaris Car App)"]
        subgraph Layer1 ["第一层：音频播放核心引擎 (完全独立)"]
            PlayerEngine["just_audio (ExoPlayer 1.4.1)"]
            AudioSessionManager["AudioSession (车载焦点管理)"]
            CacheManager["本地 LRU 音乐缓存 (离线化防断流)"]
        end

        subgraph Layer2 ["第二层：曲库元数据与远程控制适配层"]
            RemoteSyncService["RemoteControlSyncService (指令接收与状态上报)"]
            TrackResolver["TrackURL 解析器 (支持本地资产 / CDN流 / 后端代理流)"]
        end
    end

    UI -->|1. 搜索/选歌/控制| API_Route
    API_Route -->|2. 解析歌曲URL/歌单| NeteaseProxy
    API_Route -->|3. 派发播放指令| StateHub
    StateHub -->|4. 下发播放 Task (包含 Audio URL & Title)| RemoteSyncService
    RemoteSyncService -->|5. 调度| TrackResolver
    TrackResolver -->|6. 本地缓存或直接加载| PlayerEngine
    PlayerEngine -->|7. 硬件声道输出| AudioSessionManager
    PlayerEngine -.->|8. 实时进度/状态回传| RemoteSyncService
    RemoteSyncService -.->|9. 状态广播回传| StateHub
    StateHub -.->|10. 实时同步| UI
```

### 架构优势：
1. **车机轻量化**：车机不需要运行庞大的 Node.js 网易云逆向解析服务，所有复杂加密（Weapi/Eapi/Cookie 维护）均部署在 Ubuntu 云端，车机只接收清洁的音频 URL。
2. **离线高可用**：当车辆在隧道、地下车库或无信号区域时，底层引擎仍可播放本地缓存曲目与离线应急音频，不因网络崩溃而黑屏卡死。
3. **协议标准化**：iPhone 客户端不感知底层是官方网易云还是内置播放器，统一面向标准播控 API 交互。

## 7. 约束、限制与安全保障

1. **安全初始音量**：播放器服务强制锁定初始音量为 `0.25` (25%)，防止在车载恶劣环境下突发大音量损坏车机功放或惊扰驾驶员。
2. **车载焦点保护**：`AudioSession` 使用标准 `USAGE_MEDIA` 与 `CONTENT_TYPE_MUSIC`，当高优先级应用（如 NAVITIME 播报转弯）介入时，ExoPlayer 自动触发临时闪避 (Ducking) 或静音，播报结束后自动恢复音量。
3. **网络故障免疫**：所有本地音频资产直接嵌入在 APK 内，无需依赖网络解析；后续接入公网曲目时，必须先在内存或磁盘建立缓冲校验，URL 404 或解析失败时降级提示，不阻塞 UI。
