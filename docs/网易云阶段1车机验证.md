## 1. 问题背景与根本原因诊断

### 1.1 现象与问题陈述
在阶段 1 验证中，手机端向车机端下发 `play_track` 指令点播后端在线网易云音频时，车机 ExoPlayer 无法完成网络流式加载，抛出 `(0) Source error` 异常，在线播放失败。

### 1.2 深入底层根因分析
1. **ExoPlayer 与系统 DNS 阻断**：
   - 车机端音频引擎采用 `just_audio`，其在 Android 原生层依赖 Google ExoPlayer（`DefaultHttpDataSource`）。
   - ExoPlayer 的 HTTP 请求由 Android 原生 Java 网络协议栈发起，完全受制于 Android 系统的 DNS 解析器。
   - 实机实测证明：Ottocast P3 Pro 车机系统底层 DNS 无法解析 Tailscale 私有 MagicDNS 域名 `myyaris.example.com`（`ping` 报 `unknown host`，错误码 2）。
2. **Dart 层 DNS 回退无法穿透原生层**：
   - 虽然 Dart 层的 `BackendClient` 配置了 `connectionFactory` 自定义回退 DNS（解析至 `192.0.2.10`），但此逻辑封装在 Dart 虚拟机内部，**无法自动覆盖原生 Android ExoPlayer 的网络请求**。
3. **原生直接直连 IP 的 TLS 校验屏障**：
   - 若将流地址直接替换为 `https://192.0.2.10/...`，ExoPlayer 原生 TLS 握手将因缺少 SNI 或证书 SAN 不匹配（证书颁发对象为 `*.ts.net`）而被拒绝。
   - 用户及安全准则严格要求：**禁止 HTTP 明文降级、禁止信任所有证书、禁止擅自修改全机 DNS 或 Tailscale 虚拟网卡配置**。

## 2. 最小侵入应用内架构实现：`InAppAudioStreamProxy`

车机端通过应用内本地环回流式代理机制，彻底解决了 ExoPlayer 原生 DNS 阻断问题，同时保持 100% 严格 TLS 证书链验证与 SNI 完整性。

```
+-------------------------------------------------------------------------------------------------+
|                                 Ottocast P3 Pro (Car Device)                                    |
|                                                                                                 |
|   +-----------------------+     HTTP 206 Range       +--------------------------------------+   |
|   | Native ExoPlayer      | =======================> | InAppAudioStreamProxy                |   |
|   | (Android Java/Kotlin) | <======================= | (Dart, binds strictly to 127.0.0.1)  |   |
|   +-----------------------+   Localhost Loopback     +-------------------+------------------+   |
|                                                                          |                      |
+--------------------------------------------------------------------------|----------------------+
                                                                           | Strict TLS / SNI
                                                                           | Connects to 192.0.2.10:443
                                                                           | Host: myyaris-user-....ts.net
                                                                           v Validated with System Root CA
+-------------------------------------------------------------------------------------------------+
|                                 R9000P Host (Backend Server)                                    |
|                                                                                                 |
|   +-----------------------------------------------------------------------------------------+   |
|   | FastAPI Media Streaming Service (/api/v1/music/netease/stream/{song_id})                 |   |
|   | - Serves HTTP 206 Partial Content from local SSD cache                                  |   |
|   +-----------------------------------------------------------------------------------------+   |
+-------------------------------------------------------------------------------------------------+
```

### 2.1 核心特性
1. **严格保持 HTTPS 与证书链安全**：
   - 环回代理通过 `BackendClient.httpClient` 与上游后端建立连接，严格走 HTTPS、发送 SNI `myyaris.example.com`，并由 Android 系统受信任 CA 证书库完成证书链校验。
   - 不修改上游协议为 HTTP 明文，不包含任何绕过证书检查的代码。
2. **局域安全隔离配置**：
   - 新增 `android/app/src/main/res/xml/network_security_config.xml`，仅明确允许 `127.0.0.1` 与 `localhost` 环回接口走明文 IPC。
   - 所有外部非环回域名一律强制要求严格 HTTPS。
3. **HTTP 206 Partial Content 与 Range 完整透传**：
   - 完整代理并透传客户端 `Range` 请求头、上游 `Content-Range`、`Content-Length`、`Content-Type` 与 `Accept-Ranges: bytes`，保证 ExoPlayer 能自如进行 Seek、进度拖拽与分片拉取。
4. **安全鉴权请求头自动注入**：
   - 代理检测目标为私有车机后端地址时，自动附带 `X-Device-Token` 与 `Authorization: Bearer <token>`，免去原生播放器配置复杂请求头的脆弱性。
