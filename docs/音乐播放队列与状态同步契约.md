## 1. 业务背景与核心架构原则

### 1.1 演进背景
在 MyYaris 早期实现中，车载音乐播放仅支持单曲点播（`play_track`）或 3 首内置测试样本音轨，历史设计曾构想过由手机客户端后台代理切歌，但受限于手机系统后台保活机制与网络抖动，无法稳定保障离线与弱网下的持续行车听歌体验。同时，既有实现缺乏全量喜欢歌单索引、心动模式存在降级伪装、且随机播放容易发生小范围循环。

本契约正式冻结 **V2.2 音乐播放队列与全状态同步架构**，确立**车机自主维护全量队列连续播放**、**真实心动模式**与**多端显式状态闭环**的工业级规范。

### 1.2 核心底线与不可违背原则 (Non-Negotiable Principles)

1. **默认队列源为已验证 Owner 的网易云「我喜欢的音乐」**：
   - 车机启动或重置队列时的默认播放源必须为当前登录 Owner 账号的系统喜欢歌单 (`source="netease_favorite"`)；
   - 歌单所有权必须严格依据第三方接口规范通过 `specialType == 5` 及 `creator.userId == current_owner_uid` 动态判定，严禁依赖硬编码歌单 ID 或文本名称模糊匹配；
   - 若当前 Owner 喜欢歌单曲目数为 0，服务端直接返回 `HTTP 409 Conflict` (`error_code: "EMPTY_PLAYLIST"`)，禁止创建不可播空队列。
2. **列表循环与随机播放必须限定并覆盖全量喜欢歌单**：
   - `list_loop`（顺序列表循环）与 `shuffle`（随机播放）必须覆盖当前喜欢歌单的**全部曲目**（如 500~800+ 首全部音轨）；
   - **严禁仅截取前 30 首第一页**，**严禁使用内置本地测试样本代替**；
   - 车机端负责基于全量队列音轨索引独立完成连续切歌与播放调度。
3. **零自动播放精确定义 (Zero Auto-Play)**：
   - **冷启动**：车机应用启动或系统初始化时，静默拉取/加载队列快照，播放状态保持为 `stopped` 或 `paused`，**绝不自动开声播放**；
   - **WebSocket 重连 / 前台恢复**：仅执行状态与快照对齐，**不触发新播放，亦绝不打断/暂停当前正在正常播放的音乐**；
   - **模式切换**：执行 `set_playback_mode` 或 `switch_queue` 时，若当前处于暂停/停止状态，**保持暂停/停止**，仅重构播放序列；只有用户显式发起播放指令（`resume` / `play_track`）时才真正输出音频。
4. **真实心动模式 (Authentic Intelligence Mode) 严格约束**：
   - 心动模式必须生成专用的独立推荐队列 (`source="netease_intelligence"`)；
   - **初始种子曲目资格**：初始启动心动模式的 `seed_song_id` 必须属于当前已验证 Owner 的喜欢歌单，不合规种子直接拒绝；
   - **后续推荐特性**：心动模式后续推荐曲目为网易云个性化流，不保证均在喜欢歌单内；
   - **严格真实性**：严格要求必须来源于网易云上游真实的 `/playmode/intelligence/list` 接口；
   - **严禁伪装降级**：**严禁将相似歌曲降级 (`mode="simi_fallback"`) 或空列表 (`mode="empty"`) 伪装为心动模式成功**；
   - 若上游凭证失效（返回 301/401）返回 **HTTP 409 Conflict** (`error_code: "INTELLIGENCE_AUTH_INVALID"`)，上游服务异常返回 **HTTP 502/503**；车机端保留原播放状态与原队列，绝不中断当前歌曲，**绝不自动触发重新登录，绝不私自调用点赞或取消红心 (`like/unlike`) 接口**；
   - **耗尽与熔断**：当心动队列曲目播放完毕且续批失败时，播放器直接进入 `stopped` 状态并报告可见错误，绝不静默 fallback 到普通随机。
5. **媒体流 URL 按需获取与全歌单不过期原则**：
   - 队列元数据接口返回的 `stream_url` 必须为**相对路径**（例如 `/api/v1/music/netease/stream/{song_id}`）或经过服务端反代的可信 HTTPS 路径，**严禁返回客户端不可达的 `127.0.0.1` 或硬编码私网地址**；
   - 严禁全量预拉取 CDN 临时 URL 以免 Token 过期；车机仅在当前播放曲目时按需拉取媒体流；
   - 音轨权限 `playable` 若未校验或上游未明确指示，**固定返回 `null`**，严禁未经核实默认填充为 `true`。
6. **连续失败跳过熔断上限 (Consecutive Failure Circuit Breaker)**：
   - 遇到 VIP 限制、音频下架、解码失败或网络超时时，车机可自动跳过该曲目尝试下一首；
   - **强制设定连续失败熔断上限为 3 首**：若连续 3 首均无法正常播放，车机音频引擎必须立即停止跳动进入 `stopped` 状态，并在状态中回报可见错误码 `PLAYBACK_CONSECUTIVE_FAILURES`，彻底防止无限快速空转。
7. **搜索点歌与默认喜欢歌单的显式隔离**：
   - 搜索点歌创建显式**临时单曲队列** (`source="single_track"`)，播放完毕后停止 (`stopped`)；
   - 从搜索单曲返回喜欢歌单必须为**显式用户操作**（点击“返回喜欢歌单”或切换模式）；
   - 返回喜欢歌单时，若该单曲存在于喜欢歌单内，按稳定 `track_id` 恢复其在喜欢歌单中的原索引位置，否则回退到 `index 0`。
8. **新旧能力协商与旧指令安全映射**：
   - 车机通过 `capabilities` 声明是否支持 `queue_v2`；
   - 旧客户端调用新语义（如尝试使用全量队列特性）若车机不支持，服务端与车机返回明确的 `CAPABILITY_NOT_SUPPORTED` 拒绝，不在 UI 伪报成功；严禁将旧版 3 首本地样本视作正常功能完成。

## 2. 账号/设备隔离与队列标识规范

### 2.1 账号与设备严格绑定
1. **设备鉴权边界**：
   - 手机客户端 (`phone`) 只能查询与控制其经过鉴权绑定的目标车机设备；
   - 车机客户端 (`car`) 只能拉取与操作属于自身 `device_id` 的播放队列与状态；
2. **账号切换清理**：
   - 当网易云账号注销或切换绑定 Owner 时，服务端原子清空该设备关联的缓存队列快照；
3. **安全脱敏标识 (Opaque Queue ID)**：
   - 队列唯一标识符 `queue_id` 必须采用**不含用户账号 ID、不含网易云 UID 的 Opaque 散列标识**：
     - 喜欢歌单队列：`q_fav_<sha256(owner_uid + pid)[:12]>`（例如 `q_fav_a1b2c3d4e5f6`）
     - 心动推荐队列：`q_intel_<sha256(seed_id + ts)[:12]>`（例如 `q_intel_7f8a9b0c1d2e`）
     - 临时单曲队列：`q_single_<sha256(song_id + ts)[:12]>`（例如 `q_single_9e8d7c6b5a4f`）

### 3.3 标准错误响应结构与枚举表

统一错误格式：
```json
{
  "code": 409,
  "error_code": "QUEUE_VERSION_CONFLICT",
  "error_detail": "Requested queue version 101 does not match current snapshot version 102.",
  "message": "播放队列版本已变更，请从第一页重新拉取。"
}
```

#### 统一错误码枚举 (`error_code`)

| HTTP 状态码 | 错误码 (`error_code`) | 含义与触发场景 | 客户端处理行为 |
| :--- | :--- | :--- | :--- |
| **`404 Not Found`** | `TRACK_NOT_IN_QUEUE` | 请求点播的目标曲目不在指定的队列快照成员列表中 | 客户端刷新队列快照或作为单曲点播重试 |
| **`409 Conflict`** | `QUEUE_VERSION_CONFLICT` | 分页请求或指令目标传入的 `queue_version` 与服务端当前或指定快照版本不一致 | 车机或手机清空本地缓存，从 `offset=0` 重新拉取新快照 |
| **`409 Conflict`** | `EMPTY_PLAYLIST` | 当前 Owner 喜欢歌单曲目数为 0 | 提示用户“喜欢歌单为空”，不创建播放队列 |
| **`409 Conflict`** | `QUEUE_NOT_READY` | 当前队列正在构建或处于未就绪状态 | 客户端退避 1~2 秒后重试 |
| **`409 Conflict`** | `INTELLIGENCE_AUTH_INVALID` | 网易云会话凭证失效或未登录 | 提示“网易云登录凭证失效，心动模式不可用”，不自动弹窗登录 |
| **`409 Conflict`** | `COMMAND_CONFLICT` | 相同 `command_id` 携带不同动作或参数 | 检查客户端指令 ID 生成逻辑，避免指令冲突 |
| **`409 Conflict`** | `QUEUE_PRECONDITION_FAILED` | 指令携带的 `expected_queue_id` 或版本与当前实际激活队列不符 | 客户端拉取最新状态后重新评估是否发送指令 |
| **`403 Forbidden`** | `OWNER_QUEUE_PERMISSION_DENIED` | 普通注册用户 (`role="user"`) 尝试操作或点播 Owner 专属喜欢歌单/心动队列 | 提示无权操作车主专属资产 |
| **`422 Unprocessable`** | `QUEUE_SOURCE_MISMATCH` | 指令声明的 `source` 与指定 `queue_id` 快照实际来源不匹配 | 检查入参队列源标识与快照归属 |
| **`422 Unprocessable`** | `QUEUE_INDEX_MISMATCH` | 指令传入的 `queue_index` 越界或与目标曲目 ID 不匹配 | 检查曲目索引对齐逻辑 |
| **`422 Unprocessable`** | `CAPABILITY_NOT_SUPPORTED` | 车机上报能力中缺少 `queue_v2`，无法执行新队列指令 | 提示用户“车机版本过低，请升级车机端软件” |
| **`502 Bad Gateway`** | `INTELLIGENCE_UPSTREAM_FAILED` | 网易云心动模式上游接口网络异常或返回非 200 | 保留原播放状态与当前曲目，提示“心动模式服务暂不可用” |
| **`503 Unavailable`** | `INTELLIGENCE_QUEUE_EXHAUSTED` | 心动队列推荐曲目已播放完毕且续批多次失败 | 播放器进入 `stopped` 状态，提示用户切回喜欢歌单 |

## 4. 详细接口规范与不可变快照约束

### 4.1 获取当前队列元数据与分页音轨 (`GET /api/v1/music/queue`)

- **纯读保护约束**：
  - 本接口为**纯幂等读接口**，传入 `?source=...` 仅作为条件过滤查询，**绝对不产生激活队列、切换当前队列或改变播放状态的任何副作用**；
  - **快照缓存优先查找**：携带 `(queue_id, queue_version)` 查询时，优先命中不可变快照及待定快照缓存返回，不依赖激活队列，亦不触发“我喜欢的音乐”外部生成，冷启动或独立单曲查询完全隔离；
  - **冷启动缺省查询无激活**：在无活跃播放队列时直接调用缺省 `GET /queue`，服务端仅准备临时不可变只读视图 (`activate=False`)，**绝不将该队列注入 `_active_queues` 活跃播放态**；
  - 队列的激活与切换必须且只能通过显式播控指令 (`switch_queue` / `set_playback_mode` / `play_track`) 并由车机上报 `applied` ACK 完成。
- **不可变快照分页规则**：
  - **首次拉取或探查 (`offset == 0`)**：客户端可不传 `queue_id` 与 `queue_version`，服务端返回当前激活队列（若无则返回未激活的喜欢歌单视图）的第 0 页及确定的 `queue_id`、`queue_version`；
  - **后续分页拉取 (`offset > 0`)**：客户端**必须显式携带**此前第一页返回的 `queue_id` 与 `queue_version`；
  - **版本冲突拦截**：若传入的 `queue_version` 与服务端当前不符，服务端立即返回 **HTTP 409 Conflict (`QUEUE_VERSION_CONFLICT`)**；车机收到 409 后丢弃脏分页，进行有界重拉（最多重试 3 次），严禁拼接混合不同版本的音轨页。

### 4.2 心动模式生成与动态续批规范 (`POST /api/v1/music/netease/intelligence`)

- **方法 & 路径**：`POST /api/v1/music/netease/intelligence`
- **鉴权**：`phone` / `car` / `admin`
- **请求体**：
  ```json
  {
    "request_id": "req_intel_88a7b6c5d4e3", // 客户端唯一幂等请求ID
    "seed_song_id": 1901371647,             // 种子歌曲数字ID
    "playlist_id": 987654321,               // 喜欢歌单ID
    "batch_index": 0,                       // 批次序号 (0为首批，>0为续批)
    "count": 30                             // 请求数量 (默认30)
  }
  ```
- **核心契约逻辑**：
  1. **首批种子合法性校验 (`batch_index == 0`)**：
     - 后端校验 `seed_song_id` 是否属于当前 Owner 验证通过的喜欢歌单 (`netease_favorite`)；
     - 若种子曲目不在喜欢歌单中，返回 **HTTP 422 Unprocessable Entity**（`detail: "Initial intelligence seed song must belong to owner favorite playlist"`）；
  2. **续批合法种子与幂等防重放 (`batch_index > 0`)**：
     - 续批时的 `seed_song_id` 必须为前序心动批次中已推荐的最后一首曲目（`last_song_id`）或车机当前正在播放的心动曲目，严禁客户端随意挑选非本队列歌曲作为种子；
     - 携带 `request_id` 进行幂等去重；若网络重发相同 `request_id`，直接返回既有续批结果；
     - **续批上限保护**：单次心动会话续批次数上限为 5 次（总曲目上限 150 首），达到上限后不再向网易云无限请求；
  3. **新版本生成与原有索引稳定性保证**：
     - 追加新一批曲目时，原有已加载的 `0..old_total-1` 首曲目及索引**绝对保持不变**；
     - 新推荐曲目追加至 `old_total..new_total-1`，总数更新为 `new_total = old_total + count`；
     - 队列版本递增：`queue_version = old_version + 1`；
     - 车机当前的 `current_index` 保持连续有效，绝不跳帧或回退。

### 4.3 播控指令扩展与前置条件校验 (`POST /api/v1/music/control/command`)

- **方法 & 路径**：`POST /api/v1/music/control/command`
- **请求体扩展字段**：
  ```json
  {
    "command_id": "cmd_music_88a7b6c5d4e3",
    "device_id": "car_example",
    "action": "set_playback_mode",
    "params": {
      "mode": "intelligence",
      "seed_track_id": "netease_1901371647",
      "expected_queue_id": "q_fav_a1b2c3d4e5f6",
      "expected_queue_version": 102
    },
    "expires_in_seconds": 30
  }
  ```
- **前置条件与冲突判定**：
  - **HTTP与WebSocket同构管线**：HTTP `POST /music/control/command` 与 WebSocket `type: "command"` 共享同一套指令处理管线，强制执行完全一致的鉴权、参数校验、前置条件判定与状态流转；
  - **Owner 专属资产门禁**：普通用户 (`role == "user"`) 即使拥有车机控制权限，亦**严禁执行 `set_playback_mode`、`switch_queue` 或在无活跃队列时 `resume`**（HTTP 返回 403 Forbidden，WS 返回 status: error / code: 403 / error_code: `OWNER_QUEUE_PERMISSION_DENIED`）；
  - **Seek 参数归一化与校验**：接受 `seek_position_ms` / `seek_ms` / `position_ms`，多字段值冲突直接返回 **HTTP 422** (`SEEK_PARAMETER_CONFLICT`)，缺少跳转参数返回 **HTTP 422** (`SEEK_PARAMETER_REQUIRED`)，负数进度返回 **HTTP 422** (`INVALID_SEEK_POSITION`)；
  - **歌单成员点播与原子状态流转 (`play_track`)**：
    - **显式喜欢歌单成员点播 (`source="netease_favorite"`)**：
      - 客户端携带 `queue_id`、`queue_version`、`song_id` / `track_id` 及可选 `queue_index`；
      - 服务端基于目标设备从不可变快照缓存与待定快照中精确检索对应快照：
        - 若快照已失效、不存在或版本不符，直接返回 **HTTP 409 Conflict** (`QUEUE_VERSION_CONFLICT`)；
        - 若快照实际来源非 `netease_favorite`，直接返回 **HTTP 422** (`QUEUE_SOURCE_MISMATCH`)；
        - 若指定曲目不在该快照音轨成员中，直接返回 **HTTP 404 Not Found** (`TRACK_NOT_IN_QUEUE`)；
        - 若显式传入 `queue_index` 但索引越界或对应位置音轨与 `song_id` 不符，直接返回 **HTTP 422** (`QUEUE_INDEX_MISMATCH`)；
        - 普通用户角色 (`role == "user"`) 尝试发起喜欢歌单成员点播，直接返回 **HTTP 403 Forbidden** (`OWNER_QUEUE_PERMISSION_DENIED`)；
        - **零指令断言 (Zero Eager Command)**：上述任一校验失败均在指令落库创建前抛出异常，断言数据库不产生任何 `MusicCommand` 垃圾记录，且活跃队列绝对保持不变；
      - 校验通过后：
        - 服务端将该快照登记为对应 `command_id` 的准备态快照 (`register_pending_snapshot`)；
        - **不分配新队列版本号**（保持原快照版本）；
        - **在车机回执 ACK 前绝不提前激活**（`_active_queues` 保持原状）；
        - 自动注入 `queue_id`、`queue_version`、`source="netease_favorite"`、`queue_index`、`stream_url` 及完整元数据交付车机；
    - **显式单曲点播 (`source="single_track"`)**：准备独立单曲队列，单调分配递增版本号；
    - **缺省兼容点播 (未传 `source`)**：若目标曲目属于当前已激活队列，维持原队列源并更新索引；否则准备临时 `single_track` 队列；
    - **前置条件断言与当前队列解耦**：若指令附带 `expected_queue_id` / `expected_queue_version`，其断言比对对象为**车机当前实际已生效的活跃队列 (`active_q`)**，绝非手机端正在浏览的点播目标快照；
    - **车机执行回执流转 (ACK Promotion)**：
      - 收到 `applied` ACK 时，将该快照正式提升为车机活跃队列 (`_active_queues`)，车机状态表原子更新 `queue_id`、`queue_version`、`queue_source="netease_favorite"`、`current_index`，并自动对齐 `applied_mode="list_loop"`；
      - 收到 `failed` ACK 时，安全丢弃待定快照，活跃队列与车机状态保持不变；
  - **Resume 错误显式暴露**：在无激活队列下发起 `resume` 时，若喜欢歌单初始化失败（未登录或歌单为空），**严禁静默吞掉异常**，必须显式返回 **HTTP 409 Conflict** (`INTELLIGENCE_AUTH_INVALID` / `EMPTY_PLAYLIST`)，不创建新指令，不向车机派发；
  - **准备态与应用态解耦 (Pending / Applied State Machine)**：指令生成阶段仅在服务端注册准备态快照 (`_pending_queues`)，绝不立即替换车机当前活跃队列 (`_active_queues`)，且绝不提前修改车机状态表中的 `queue_id` 与 `queue_version`；仅当车机真正执行完成并上报 `applied` ACK（通过 HTTP ACK 或 WS `command_ack` 或状态上报 `last_applied_command_id`）时，才将 pending 快照提升为 active 队列并更新车机状态；车机执行失败或超时丢弃 pending 快照，当前活跃队列与车机状态完全不受破坏；且迟到 ACK 无法覆盖更新的活跃队列；
  - **独立 SQLite 水位序列计数器表 (`queue_version_sequences`)**：`queue_version` 的单调递增水位分配完全由独立的 `queue_version_sequences` 表持久化维护，彻底与车机实际应用状态表 `CarDeviceStatus` 解耦，杜绝在准备态或指令失败超时时篡改车机实际状态版本号；系统时钟回拨或进程真体重启均严格保证单调递增与防碰撞；
  - **幂等性**：相同 `command_id` + 相同 payload 返回已存在的同一执行结果；相同 `command_id` + 不同 payload 返回 **HTTP 409 Conflict** (`COMMAND_CONFLICT`)；
  - **前置条件断言**：若指令携带 `expected_queue_version` 或 `expected_queue_id`，当服务端当前队列不一致时，返回 **HTTP 409 Conflict** (`QUEUE_PRECONDITION_FAILED`)，防止竞态冲突；
  - **能力门禁**：若目标车机上报的 capabilities 中缺少 `queue_v2`，对于 `set_playback_mode` 或 `switch_queue` 指令直接返回 **HTTP 422** (`CAPABILITY_NOT_SUPPORTED`)，杜绝旧车机静默忽略导致假成功。

### 4.4 车机状态上报与单调序列号 (`POST /api/v1/music/control/status`)

- **方法 & 路径**：`POST /api/v1/music/control/status`
- **单调序列保护与迟到 ACK 隔离**：
  - 上报载荷包含 `status_seq`（单调递增整数）与 `last_applied_command_id`；
  - 后端接收状态快照时，仅当 `status_seq >= current_status_seq` 时才全量更新快照；
  - 迟到的旧指令 ACK 回执受终态保护，**绝不能将状态机从 `applied` 回退至 `received`，亦绝不以旧状态快照覆盖新状态快照**。

## 5. 最小化实施决策与车机端执行规范 (Minimal Implementation Decisions)

为确保工程落地的高可靠性与快速收敛，第一阶段确立以下最小实现决策：

1. **车机端元数据内存快照 (In-Memory Snapshot Only)**：
   - 第一版车机端仅在 Dart 内存中维护当前队列的音轨元数据列表与排列索引；
   - **不引入本地 SQLite / Hive 复杂数据库依赖**；车机冷启动时静默重新校验并拉取队列首批快照；
2. **第一版不预加载媒体流 (No Speculative Preload)**：
   - 切歌时按需请求流媒体代理，避免复杂的预加载流式缓存及 CDN Token 失效问题；
3. **全量随机播放激活门槛**：
   - 仅在车机端获取到当前喜欢歌单的完整元数据后，才允许启用全量无放回 `shuffle`；未拉取完毕前保持顺序分页模式；
4. **单曲点播与返回喜欢恢复算法**：
   - 点播单曲播放结束自然停止 (`stopped`)；
   - 用户切回喜欢歌单时：
     - 若该单曲存在于喜欢歌单内，定位至该曲在喜欢歌单中的对应索引继续播放；
     - 若该单曲不在喜欢歌单内，平滑回退至第 0 首准备播放。
