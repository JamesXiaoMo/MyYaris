## 1. 业务背景与核心架构原则

### 1.1 演进背景
在 MyYaris 既有实现中，音乐播放主要基于单曲点播（`play_track`）、3 首内置测试样本音轨或由手机客户端后台频繁代发 `next` 指令驱动下一曲。该模式存在无法脱离手机后台、仅覆盖前 30 首喜欢歌单、随机播放容易陷入死循环或重复、心动模式降级伪装以及弱网下切歌异常等问题。

本契约正式冻结 **V2.2 音乐播放队列与全状态同步架构**，确立**车机自主维护全量队列连续播放**、**真实心动模式**与**多端显式状态闭环**的工业级规范。

### 1.2 核心底线与不可违背原则 (Non-Negotiable Principles)

1. **默认队列源为已验证 Owner 的网易云「我喜欢的音乐」**：
   - 车机启动或重置队列时的默认播放源必须为当前登录 Owner 账号的系统喜欢歌单 (`source="netease_favorite"`)；
   - 歌单所有权必须严格依据第三方接口规范通过 `specialType == 5` 及 `creator.userId == current_owner_uid` 动态判定，严禁依赖硬编码歌单 ID 或文本名称模糊匹配。
2. **列表循环与随机播放必须限定并覆盖全量喜欢歌单**：
   - `list_loop`（顺序列表循环）与 `shuffle`（随机播放）必须覆盖当前喜欢歌单的**全部曲目**（如 500~800+ 首全部音轨）；
   - **严禁仅截取前 30 首第一页**，**严禁使用内置本地测试样本代替**，**严禁依赖手机客户端后台长跑轮询或代发下一曲指令**；
   - 车机端负责基于全量队列音轨索引独立完成连续切歌与播放调度。
3. **打开 App / 会话恢复零自动播放 (Zero Auto-Play on App Launch / Reconnect)**：
   - 车机系统启动、应用前台唤醒、WebSocket 断线重连或服务端进程重启时，**绝不自动恢复出声播放**；
   - 恢复会话仅恢复当前队列上下文与上次暂停的音轨元数据，播放状态保持为 `stopped` 或 `paused`；
   - 只有当用户显式点击播放（`resume` / `play_track`）或显式切换播放模式时，才允许改变音频输出状态。
4. **真实心动模式 (Authentic Intelligence Mode) 约束**：
   - 心动模式必须生成专用的独立推荐队列 (`source="netease_intelligence"`)；
   - 严格要求必须来源于网易云上游真实的 `/playmode/intelligence/list` 接口；
   - **严禁将相似歌曲降级 (`mode="simi_fallback"`) 或空列表 (`mode="empty"`) 伪装为心动模式成功**；
   - 若上游凭证失效、未登录或心动接口返回异常，服务端必须直接返回明确错误（如 `HTTP 409` / `502`）；车机端保留原播放状态与原队列，绝不中断当前歌曲，**绝不自动触发重新登录，绝不私自调用点赞或取消红心 (`like/unlike`) 接口**。
5. **媒体流 URL 按需获取与全歌单不过期原则**：
   - 队列分页与全量索引同步时仅传输音轨元数据（ID、标题、艺术家、时长等），**严禁批量预拉取并缓存全歌单几百首音频直链**（避免 CDN 临时 Token 过期导致后续切歌 403）；
   - 车机仅在当前播放曲目及预加载下一首（至多提前一首）时，按需调用流媒体代理接口 (`/api/v1/music/netease/stream/{song_id}`)；
   - 媒体代理严格支持 **RFC 7233 HTTP Range 分片传输**（HTTP 206 Partial Content）。
6. **连续失败跳过熔断上限 (Consecutive Failure Circuit Breaker)**：
   - 当遇到 VIP 限制、音频下架、解码失败或网络超时时，车机可自动跳过该曲目尝试下一首；
   - **强制设定连续失败熔断上限为 3 首**：若连续 3 首均无法正常播放，车机音频引擎必须立即停止跳动进入 `stopped` 状态，并在状态中回报可见错误码 `PLAYBACK_CONSECUTIVE_FAILURES`，彻底防止断网或权限受限时的无限快速空转。
7. **搜索点歌与默认喜欢歌单的显式隔离**：
   - 用户临时搜索点歌时，系统创建显式的**临时单曲队列** (`source="single_track"`)，播放单曲而不污染用户当前完整喜欢歌单队列；
   - 从搜索单曲返回喜欢歌单必须为**显式用户操作**（如点击“返回喜欢歌单”或点击切换播放模式）。

## 2. 队列标识与数据模型 (Queue Data Schema)

### 2.1 队列元数据模型 (`MusicQueueInfo`)

| 字段名 | 类型 | 必填 | 说明 | 示例 |
| :--- | :--- | :---: | :--- | :--- |
| `queue_id` | String | 是 | 当前队列唯一标识符 | `"q_fav_12345678_987654321"` |
| `queue_version` | Integer | 是 | 队列单调递增版本号，歌单变更或模式重构时递增 | `102` |
| `source` | String | 是 | 队列源类型：`"netease_favorite"` \| `"netease_intelligence"` \| `"single_track"` | `"netease_favorite"` |
| `playlist_id` | String/Int | 否 | 外部歌单 ID（喜欢歌单或心动参考歌单） | `987654321` |
| `total` | Integer | 是 | 当前队列包含的音轨总数（真实全量） | `842` |
| `is_complete` | Boolean | 是 | 全量音轨数量是否已确立完备 | `true` |
| `page_size` | Integer | 是 | 当前元数据分页大小（推荐 50，上限 100） | `50` |
| `total_pages` | Integer | 是 | 元数据分页总页数：`ceil(total / page_size)` | `17` |
| `updated_at` | String | 是 | 队列版本生成时间 (ISO 8601 UTC) | `"2026-10-19T12:00:00Z"` |

### 2.2 播放模式定义 (`PlaybackMode`)

系统统一定义 4 种播放模式枚举：

```
playback_mode:
  - "list_loop":      顺序列表循环（在完整全量喜欢歌单中从 0..total-1 顺序循环播放）
  - "shuffle":        全量随机播放（基于全量喜欢歌单建立无放回随机排列，全集播完前不重复）
  - "intelligence":   心动模式（由网易云专属算法独立生成的个性化推荐队列，动态续曲）
  - "single_loop":    单曲循环（单曲原地循环，保留兼容）
```

### 2.3 车机播放器全状态模型 (`CarDeviceStatus`)

车机通过 WebSocket 或 HTTP `POST /api/v1/music/control/status` 上报的状态快照，必须严格区分**车机当前实际应用的模式/队列**与**最新请求的模式/队列**：

```json
{
  "device_id": "car_p3pro",
  "playback_state": "playing",           // "playing" | "paused" | "stopped"
  "applied_mode": "list_loop",           // 车机当前音频引擎实际运行的模式
  "requested_mode": "list_loop",         // 服务端/手机端最新期望的模式
  "queue_id": "q_fav_12345678_987654321",// 车机当前加载的队列ID
  "queue_version": 102,                  // 车机当前生效的队列版本
  "queue_source": "netease_favorite",    // "netease_favorite" | "netease_intelligence" | "single_track"
  "current_index": 45,                   // 当前播放歌曲在全量队列中的绝对索引 (0 <= index < total)
  "current_track_id": "netease_1901371647", // 当前音轨唯一ID
  "title": "海阔天空",
  "artist": "Beyond",
  "position_ms": 78200,                  // 播放进度 (毫秒)
  "duration_ms": 326000,                 // 总时长 (毫秒)
  "software_volume": 0.25,               // 软件音量 (0.0 ~ 1.0)
  "consecutive_failures": 0,             // 当前连续失败计数 (到达3时熔断)
  "error_code": null,                    // 异常错误码，如 "PLAYBACK_CONSECUTIVE_FAILURES"
  "error_detail": null,                  // 异常详情
  "capabilities": [                      // 车机端支持的能力标识
    "queue_v2",
    "intelligence_v1",
    "full_favorite_shuffle"
  ],
  "updated_at": "2026-10-19T12:00:05Z"
}
```

### 3.2 播控指令扩展与模式切换 (`POST /api/v1/music/control/command`)

- **方法 & 路径**：`POST /api/v1/music/control/command`
- **鉴权**：`phone` / `admin`
- **请求体 (`MusicCommandRequest`) 扩展 action 枚举**：

| Action 名称 | 动作语义 | 参数字段 (`params`) |
| :--- | :--- | :--- |
| `set_playback_mode` | 显式切换播放模式 | `mode`: `"list_loop"` \| `"shuffle"` \| `"intelligence"` \| `"single_loop"`<br>`seed_track_id`: 可选，心动模式种子曲目 ID |
| `switch_queue` | 显式切换队列源 | `source`: `"netease_favorite"` \| `"netease_intelligence"` \| `"single_track"`<br>`start_index`: 起始音轨索引 (默认 0)<br>`start_track_id`: 可选起始音轨 ID |
| `play_track` | 指定曲目播放 | `track_id`: 音轨 ID<br>`queue_id`: 所属队列 ID<br>`queue_index`: 在队列中的绝对索引<br>`stream_url`: 可选直链（若缺省车机自动按需合成） |
| `next` | 下一曲 | 无或携带当前 `queue_version` |
| `prev` | 上一曲 | 无或携带当前 `queue_version` |
| `pause` | 暂停播放 | 无 |
| `resume` | 继续播放 | 无 |
| `stop` | 停止播放 | 无 |
| `seek` | 进度跳转 | `position_ms`: 跳转目标毫秒数 (TTL 20秒) |
| `set_volume` | 软件音量 | `volume`: 0.0 ~ 1.0 (TTL 20秒) |

- **模式切换指令示例**：
  ```json
  {
    "command_id": "cmd_mode_88a7b6c5d4e3",
    "device_id": "car_p3pro",
    "action": "set_playback_mode",
    "params": {
      "mode": "intelligence",
      "seed_track_id": "netease_1901371647"
    },
    "expires_in_seconds": 30
  }
  ```

### 3.3 真实心动模式接口规范 (`POST /api/v1/music/netease/intelligence`)

- **方法 & 路径**：`POST /api/v1/music/netease/intelligence`
- **鉴权**：`phone` / `car` / `admin`
- **请求体**：
  ```json
  {
    "seed_song_id": 1901371647,
    "playlist_id": 987654321,
    "count": 30
  }
  ```
- **核心契约保障**：
  1. **种子曲目合法性**：`seed_song_id` 必须为有效网易云音轨数字 ID；
  2. **真实上游校验**：后端仅请求上游第三方 `/playmode/intelligence/list`。若返回 `code == 200` 且包含真实列表，返回 `mode: "intelligence"`；
  3. **严禁伪装降级**：
     - 若未登录或上游返回 301：返回 **HTTP 409 Conflict**（`detail: "网易云登录凭证失效或未登录，心动模式不可用"`）；
     - 若上游服务异常或返回空列表：返回 **HTTP 502 Bad Gateway**；
     - **严禁返回 `mode: "simi_fallback"` 或 `mode: "empty"` 并当成成功处理**；
  4. **零操作副作用**：绝对不触发自动重新登录，绝对不调用 `like` 或 `unlike` 接口。

### 3.4 车机执行 ACK 回执 (`POST /api/v1/music/control/command/{command_id}/ack`)

- **方法 & 路径**：`POST /api/v1/music/control/command/{command_id}/ack`
- **请求体**：
  ```json
  {
    "status": "applied",                 // "received" | "applied" | "failed"
    "applied_mode": "intelligence",      // 车机实际已应用的播放模式
    "queue_version": 103,                // 车机已加载生效的队列版本
    "current_index": 0,                  // 切换后当前索引
    "current_track_id": "netease_1901371648",
    "error_code": null,
    "error_detail": null,
    "device_timestamp": "2026-10-19T12:00:03Z"
  }
  ```

## 4. 车机端播放调度与核心机制规范 (Vehicle Runtime Specifications)

### 4.1 全量队列列表循环 (`list_loop`)
1. **本地索引维护**：车机端从 `/api/v1/music/queue` 分页拉取全量 `total` 首曲目的基本元数据后，在车机内存（及本地持久化）中构建长度为 `total` 的播放序列 `[0, 1, 2, ..., total - 1]`；
2. **自然切歌**：当一曲播放结束（`playerState == completed`），车机自动递增索引 `next_index = (current_index + 1) % total`，并取出对应 `track_id` 进行播放；
3. **首尾循环**：当播完第 `total - 1` 首时，自然回到第 `0` 首继续播放，永不中断。

### 4.2 全量随机播放 (`shuffle`)
1. **全集无重复洗牌 (Fisher-Yates Shuffle)**：
   - 切换至 `shuffle` 模式时，车机以当前播放曲目索引为起点，将其余所有 `total - 1` 首曲目的索引进行完整的无重复随机洗牌，生成大小为 `total` 的随机排列数组 `P`；
   - 确保全集未播完前，绝不重复播放同一首歌曲；
2. **播完重新洗牌**：
   - 当洗牌数组中的全部 `total` 首曲目均播放完毕后，自动重新生成新一轮的无放回洗牌序列，实现无尽全集随机播放；
3. **独立性保障**：全量随机播放逻辑完全由车机音频服务就地计算，**绝无手机后台代发网络指令**。

### 4.3 心动模式独立队列 (`intelligence`)
1. **独立队列加载**：心动模式激活后，车机将队列源置为 `source="netease_intelligence"`，队列 ID 标记为 `q_intel_<seed_id>_<timestamp>`；
2. **流式续曲**：
   - 心动模式首批返回约 30 首曲目；
   - 当车机播放至剩余曲目少于 5 首时（`current_index >= total - 5`），车机自动在后台以当前正在播放的曲目作为新种子，静默请求下一批心动曲目并追加至队列末尾（`total` 动态增加），实现无限智能流；
3. **失败回退保障**：
   - 若用户尝试切换心动模式但网络/上游失败，车机立即提示“心动模式暂不可用”，**保持原喜欢歌单播放状态与当前曲目不中断**。

### 4.4 搜索点歌与返回喜欢歌单流转
1. **临时点播队列**：用户在手机或车机界面搜索单曲并点击播放时，触发 `switch_queue` 将源置为 `source="single_track"`，`total=1`，当前音轨即为点播曲目；
2. **返回喜欢歌单**：
   - 用户在 UI 上显式点击“返回喜欢歌单”或点击切换播放模式按钮；
   - 车机切回 `source="netease_favorite"`，恢复此前在喜欢歌单中的播放索引或从首曲继续播放。

### 4.5 连续跳过与熔断保护
```
[曲目播放异常 (403/404/DecodeError)]
               │
               ▼
   consecutive_failures += 1
               │
       ┌───────┴───────┐
       │ (failures < 3) │ (failures >= 3)
       ▼               ▼
自动跳至下一曲       【触发熔断 Circuit Break】
                   ├─ 停止播放引擎 (state = stopped)
                   ├─ 上报 error_code = "PLAYBACK_CONSECUTIVE_FAILURES"
                   └─ 提示用户“连续多首播放失败，请检查网络或会员权益”
```

## 5. 新旧客户端能力协商与兼容边界 (Compatibility & Negotiation)

1. **车机端能力上报 (`capabilities`)**：
   - 车机在建立 WebSocket 连接或发送首次状态快照时，上报自身支持的特性数组：
     `capabilities: ["queue_v2", "intelligence_v1", "full_favorite_shuffle"]`；
2. **旧版 9 Action 映射与安全边界**：
   - 若旧版客户端发送旧指令（如 `set_loop: {mode: "all"}` 或 `set_shuffle: {shuffle: true}`）：
     - 若车机已具备 `queue_v2` 能力：车机自动将 `set_loop: "all"` 映射为 `list_loop`（全喜欢歌单循环），将 `set_shuffle: true` 映射为 `shuffle`（全喜欢歌单随机）；
     - 若车机为旧版本（无 `queue_v2`）：保持原有本地 3 首或单曲播放逻辑，**严禁向用户伪报已进入全量喜欢歌单循环**；
3. **接口幂等与防重放保护**：
   - 指令执行严格遵循以 `command_id` 为主键的去重逻辑；
   - 迟到的 ACK 受到终态保护，绝不将 `applied` 状态回退或覆盖更新的指令。

## 6. 与车机端 (`car_app`) 及 iOS 端待协商项清单 (Pending Negotiation)

在后续代码实施与部署前，本契约作为基准规范，需与车机、iOS 两端协调对齐以下具体工程细节：
