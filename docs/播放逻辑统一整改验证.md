## 实际根因

1. controller 和 just_audio 同时调度。播放器初始化加载三首样例并开启原生整表循环，单首远端音源可能被原生重复，completed 不能可靠承担列表切歌。
2. 首页仍控制第三方 MediaSession，内置页与系统媒体按钮另有直接播控路径，队列来源和模式可能各自维护。
3. 部分模式切换固定使用第 0 首，暂停分支还会重载同曲；resume 的准备队列分支也可能丢失实际 cursor/position。
4. 真实心动快照的 is_complete=false 被误当成当前批次不完整，导致真实心动不能接入；续批缺少设备/队列绑定，服务端路由未传隔离持久化会话，幂等检查也曾在调用上游之后。
5. 迟到 ACK 的新旧判断晚于实际状态写入，且同 queue_id 模式变化未完全覆盖；status_seq 从 1 重启可使新进程状态持续被丢弃。
6. 仅按 command_id 防重复不足以串行不同命令与原生完成事件。部分历史测试只验证设置快照或在无效 source 处提前失败，未真正验证播放器加载/回滚。

## 最终产品规则

- 没有选择来源时，用户显式点播放才准备完整 Owner 喜欢歌单。循环顺序首尾循环，随机覆盖完整喜欢歌单；不以第一页或本地样例替代。
- 搜索明确单曲使用独立 single_track，结束停止；选择循环/随机明确回喜欢。单曲循环保留协议兼容，不作为默认或第四个主要模式。
- 心动只使用真实 intelligence 上游队列；空列表、相似歌曲回退与普通随机均不能冒充成功。生成/鉴权失败保留原状态，续批失败保留已加载批次，到耗尽时停止并提示。
- 打开 App、恢复登录、WS 重连不播放也不暂停现有音频。冷恢复只读取已有队列元数据与实际 cursor/position，等待显式播放才加载媒体。
- 切模式保留播放/暂停，同曲不重载、不归零。首页、内置页和系统媒体按钮进入相同后端命令管线；手机不后台代下一曲。
- 引擎原生循环/随机关闭，由 controller 调度单首媒体流。媒体按需加载，保持可信同源 HTTPS 和严格 TLS；连续不可播最多尝试 3 首，有可见失败原因与回滚。
- pending 仅准备，applied 才确认执行；received、applied、实际出声分别对待。未知能力或不支持语义不伪造应用成功。

新增测试实际经过真实 CarMusicSyncService、controller、just_audio 平台接口及原生事件流；后端使用真实 HTTP/WS 路由和隔离库。覆盖：

- 137 首喜欢元数据跨页完整加载，全量随机遍历并覆盖末页，媒体只加载当前一首。
- 冷快照恢复不加载媒体、不自动播；非首曲 cursor、暂停进度和正常 resume 保留；single 返回 favorite。
- 循环/随机切换不重载同曲；不同命令串行、跨 HTTP/WS 信封重复不重播；重复 completed 仅前进一次；单曲结束实际停止 fake 引擎。
- 真实心动当前批次 is_complete=false 接入；设备/队列/版本/批次字段通过 HTTP adapter；采用服务端非 +1 版本，不本地造版本。
- 续批相同 ID 仅调用一次 mock 上游、不同参数冲突；旧前缀保持；上游失败不降级；续批途中 ACK 切换来源不会把旧结果追加到新队列。
- pending 到 applied、同队列迟到 ACK、重复状态 seq、过期 ACK、跨设备/WS 角色伪装隔离。
- 默认显式播放遇不可播跳过并 ACK 实际 cursor；连续三首失败停止；原生加载失败后回滚原队列与播放状态。

iOS 原工作目录的构建曾因文件提供器自动加回 Finder/resource fork 扩展属性而失败。清理生成物后仍重现，因此在普通临时目录复制当前已跟踪工作文件构建；没有修改工程签名配置，没有操作 Keychain。该产物未做 Apple 签名或安装验收。
