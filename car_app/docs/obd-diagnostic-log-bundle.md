# Detailed OBD session logs and export bundles

Use the existing OBD diagnostic window to manually start a basic, fuel or metadata test. After it finishes, choose **保存完整诊断包** or **分享完整诊断包**, then confirm the sensitive-data notice. The ZIP contains `report.json`, `report.md`, the corresponding actual native `transport.jsonl`, and `manifest.json`. The share sheet grants only temporary read access through the narrow existing cache FileProvider. Nothing is automatically uploaded.

The logger is disabled outside explicitly started diagnostic test sessions. A session includes its core test/recovery window, followed by up to two seconds of passive late-data recording. This logging window sends no commands and changes no protocol timeout. Save/share waits for that bounded tail window, flush and native close before taking an export snapshot. A subsequent manual test closes the previous logging window; reports keep their own session handle. RX is associated with its originating transaction/session, including old-buffer context on unsent attempts. A session is forcibly stopped after 60 seconds. Events arriving after the declared session cutoff are not promised as captured.

Each JSONL line has a session ID, event sequence and monotonic/wall time. Existing original RX hex, byte length, notification sequence, MTU, write mode/UUID/start/end, transaction deadlines/first/last RX and prompt events are retained. RX adds transaction/session cumulative byte totals. Connection snapshots/state changes, cancellation, parser summaries and restoration ACK decisions join the same journal. Unavailable parameters remain null or `not_acquired`. The build uses explicit `OBD_SOURCE_FINGERPRINT` and `OBD_BUILD_VERSION` compile defines; when absent they say `not_acquired`. The native manifest also reads the installed package/version. The journal is schema 2 and the report schema 5. These records are application observations, **not Android HCI packets or a CAN-bus capture**.

The core capture cutoff and session stop are separate. JSON/Markdown are prepared from the same sealed event snapshot. The native export worker runs after append/close operations on one ordered executor, reads its real journal parts, and compares those exact bytes against the app snapshot. The manifest records hashes, lengths, durable/queued sequence positions, cutoff, stop reason, write/flush failure, truncation and native-file availability. The same export manifest is appended to JSON and Markdown. `complete_within_window` is permitted only when native bytes match and flush/close succeeded without truncation. Missing/evicted/damaged files, failed writes or unconfirmed flush produce an explicit incomplete bundle; `app-observed.jsonl` is then included as a clearly separate reconstruction, never labelled native data. The UI warns about incomplete/limited logs.

## Storage bounds

- App capture: 1 MiB of regular event data, at most 4096 regular events, at most 512 KiB queued regular data, and a 16 KiB single-record limit. A small terminal control record is reserved beyond these thresholds to state the cutoff. At a limit, recording stops explicitly rather than silently overwriting old bytes. Later data is outside the recorded window.
- Native session files: 256 KiB segments, 2 MiB maximum per session. Rotation creates new segments; it does not overwrite earlier parts of that session. Up to eight sessions/16 MiB are retained, pruning only older closed sessions. A report referring to an evicted session is explicitly incomplete.
- Saved bundles: up to eight/32 MiB in the dedicated app-private bundle directory. Share cache: up to eight/32 MiB ZIPs, with the existing 24-hour cleanup on explicit share. These limits cover the new dedicated directories; legacy private logs are not silently migrated or deleted.
- Files are in app-private `noBackupFilesDir`; the share copy alone is placed under the narrow cache provider. Disk/fsync work is off the BLE/UI thread. The first sink failure/timeout stops logging and cancels further queued sink writes, preserving the last acknowledged prefix rather than jumping across missing events. Flush has a fixed deadline and cannot label an unacknowledged queue saved.

The logger has no account/network client, cookie, token or password fields. Device names and raw identifiers can still appear in the sensitive report; no private logs or identifiers belong in public Git. No automatic reset, empty CR, retry, flow-control change or candidate polling is introduced.

Offline tests cover inactive logging, session/tail cutoffs, late bytes, sink failure/timeout, queue/event capacity, export ordering/equivalence, cancellation/concurrency and 800×480 layout. JVM tests exercise the actual native filesystem implementation, segment rotation, closed-session retention, write failure, real ZIP contents and byte equality. Run them with `python3 tools/run_obd_native_tests.py --output /tmp/obd-native-tests` using the cached Gradle Kotlin compiler. These tests and an APK build do not constitute device-side export or vehicle acceptance.
